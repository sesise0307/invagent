# 데일리 브리핑 스킬

하루치 입력을 한 편으로 묶는다. 텔레그램 '저장한 메시지'가 출발점이지만 그것만은 아니다 —
시장 신호, 보유 포트폴리오 스냅샷, 전고점 낙폭과 계좌 MDD까지 같은
브리핑 안에서 만난다. 그래서 이름이 `daily-digest`다.

섹터/종목별로 분류 후 핵심 인사이트를 추출하고, `advice` 스킬의 세 가지 관점
(가치투자/차트/매크로)을 통합해 투자 조언까지 포함한 일일 브리핑을 생성한다.

## 기본 동작 모드

설치된 `caveman` 스킬을 `full` 강도로 활성화한 뒤 작업한다. 현재 클라이언트의
기본 스킬 호출 문법을 사용한다. 대화 응답은 전부 caveman이고, **브리핑 파일은 아래 「브리핑 문체」대로
섹션마다 문체를 나눈다.**

### 브리핑 문체 (caveman 혼합)

2026-10-02 caveman 적용본과 일반본을 나란히 써 비교한 뒤 사용자가 확정했다. 압축은 숫자를 훑는
구간에서만 이득이고, 추론을 읽는 구간에서는 손실이다.

| 섹션 | 문체 | 이유 |
|---|---|---|
| 🚦 시장 상황 · 의사 결정 조언 | **caveman full** — 조사·어미 생략, 명사형 종결, 인과는 `→`, 수치는 `·`로 나열 | 수치·판정·가격선을 훑는 구간. 압축해도 정보가 빠지지 않는다 |
| 🛡️ 룰 리마인드 · 📂 섹터별 / 종목별 정리 · 💡 투자 조언 | **일반 문장** | 「그래서」「~이므로」 같은 연결어가 곧 추론이다. 화살표로 바꾸면 인과 순서가 흐려진다 |

caveman 구간에도 아래 표기는 그대로 지킨다 — 브리핑은 `find_mentions`·`analyze-stock`이 다시
검색하는 아카이브다:

- **종목명은 정식 표기**(삼성전자우·에이치브이엠·이수페타시스). 아카이브 검색이 종목명 grep이라 약칭은 걸리지 않는다.
- **금액은 원 단위 전체 숫자**(₩175,000 · ₩1,600,000).
- **판정 기호는 ✅ / ❌ / ⏳ / 🟢 / 🟡 / 🔴 / ⏸**.

## 실행 순서

### 1단계: 데이터 준비

오늘 날짜를 `YYYY-MM-DD` 형식으로 확인한 뒤, 아래 파일이 존재하는지 확인한다:
```
output/daily-digest/raw/<today>_raw.md
```

- **파일이 없으면**: 아래 명령어로 먼저 메시지를 가져온다
  ```bash
  uv run invagent fetch-messages --days 1
  ```
- **파일이 있으면**: 그대로 사용한다

`--days` 인자를 사용자가 지정했다면 해당 값을 사용하되, 파일명 날짜는 오늘 날짜 기준이다.

첨부 이미지는 같은 명령이 `output/daily-digest/media/<today>/`에 함께 내려받는다
(`--no-download-images`로 끌 수 있다). 판독은 1-4단계에서 한다.
링크 본문은 `output/daily-digest/links/<today>/`에 따로 저장되고 raw에는 경로와 요약 대기
마커만 남는다. 요약은 1-5단계에서 한다.

### 1-0단계: 준비 단계 일괄 실행

1-1(시장 신호)과 1-3-1(전고점 낙폭)은 서로 독립이다. 한 번에 돌린다.

```bash
uv run invagent daily-prep [--snapshot output/portfolio/$(date +%Y-%m-%d).md]
```

- 두 단계를 **동시에** 돌리고 입력 순서대로 한 블록으로 찍는다. 각 단계는 그대로 **비블로킹**이라
  하나가 실패해도 나머지 출력은 남고 종료 코드는 0이다.
- `--snapshot`은 **그 파일이 이미 있을 때만** 1-3-1(전고점 낙폭)을 함께 돌린다. 첫 실행에서는
  스냅샷이 1-3단계에서 만들어지므로 보통 빠지고, 그때는 1-3-1의 명령을 따로 돌린다.
  같은 날 브리핑을 다시 만들 때는 스냅샷이 이미 있으므로 둘이 한 번에 돈다.
- 아래 1-1 · 1-3-1 절의 개별 명령은 **한 단계만 다시 돌릴 때** 쓴다.
  해석 기준·임계값·출력 규칙은 그대로 각 절이 정본이다.
- HTTP 응답은 짧은 TTL로 캐시된다(모든 스킬이 공유). 캐시 오염이 의심되면 `--no-cache`.
  캐시 규칙과 끄는 법은 `market-data` 스킬 참조.

### 1-1단계: 시장 신호 수집 (StockEasy)

StockEasy 시장 분석 페이지에서 시장 신호를 수집한다:

```bash
uv run python .agents/skills/daily-digest/scripts/fetch_market_signals.py
```

출력 내용 (신호등, 오닐 빅픽처, 지수, breadth, 신용/수급)을 해석해 브리핑 템플릿 최상단
「🚦 시장 상황」 섹션에 정리한다. 단순 수치 나열이 아니라 **한줄 판단**(현재 국면 + 대응 스탠스)까지 도출한다.

2단계 raw 분류에서 나온 시황성 내용도 이 섹션의 「오늘의 주가·수급 특이사항」 불릿에 모은다
(상세 기준은 「출력 품질 기준」).

- **실패 시 (exit 1)**: 브리핑 시장 상황 섹션에 "(시장 신호 수집 실패)" 한 줄만 표기하고
  나머지 단계는 정상 진행한다. 이 단계 실패가 브리핑 생성을 블로킹해서는 안 된다.

**「레버리지 규칙 3」 판정도 이 스크립트가 함께 낸다.** 출력의 `[레버리지 규칙 3]` 줄이 정본이고
모델은 재채점하지 않는다. 판정 대상은 **지수(KOSPI·KOSDAQ)뿐**이며, 섹터 레버리지는
「레버리지 규칙 2」대로 사용자가 판단한다.

| 상수 | 값 | 근거 |
|---|---|---|
| `VOLATILE_DAY_PCT` | 5.0% | 룰 원문의 "±5% 이상 변동". **전일 종가 대비 종가** 등락률이며 장중 고저 폭은 쓰지 않는다 — 음의 복리는 종가끼리 누적되기 때문 |
| `VOLATILE_WINDOW_DAYS` | 10 | 룰 원문의 "최근 10거래일". 달력일이 아니다. 휴장일은 `market-monitor`에 행 자체가 없어 자동으로 빠진다 |
| `VOLATILE_DAY_TRIGGER` | 3 | 룰 원문의 "3일 이상" |
| 상승 예외 | 변동일이 **전부 양수**일 때만 | 룰의 "상승 방향으로 일관적인 변동은 예외". 룰 목적이 음의 복리 방지이고 음의 복리는 방향이 섞일 때 생기므로, -5%가 하나라도 끼면 예외가 깨진다. 2025-07~2026-09 실측에서 KOSPI는 예외 0일, KOSDAQ은 37일 중 2일 |

- 데이터는 1-1단계가 이미 받은 `market/market-monitor`의 KOSPI·KOSDAQ 종가(1년치 넘음)다.
  **추가 네트워크 호출이 없다.**
- 발동(⛔)하면 「🛡️ 오늘의 룰 리마인드」에 「레버리지 규칙 3」을 최우선 채택하고,
  「매매규칙 5」가 허용하는 **즉시 전량 정리** 두 사유 중 하나임을 함께 적는다.
- 임계값을 바꾸면 스크립트 상단 상수와 이 표를 함께 고친다.

**「레버리지 규칙 2」 반대매매 클라이맥스도 같은 스크립트가 낸다.** 지수 급락에서 지수 레버리지
신규 매수가 허용되는 조건이고, **지수 한정**이다(섹터는 사용자 판단).

| 상수 | 값 | 근거 |
|---|---|---|
| `MARGIN_CALL_SIGMA` | 2 | 사용자가 정한 값 (2026-09-05). "평소 대비 +2σ 이상". **올리면 오히려 나빠진다** — 2.5σ는 발동을 14→11건으로 줄이면서 정작 2026-07-30 클라이맥스를 잘라냈다(직전 몇 달의 높은 반대매매가 기준선을 밀어올린 탓). 3.0σ는 07-30·07-31을 둘 다 놓친다 |
| `MARGIN_CALL_MIN_DRAWDOWN_PCT` / `MARGIN_CALL_PEAK_WINDOW` | -10% / 250일 | 사용자 조건의 "**지수 급락** → 반대매매 클라이맥스"를 국면으로 읽은 것. 그날 등락률로 읽으면 실패한다 — 실제 클라이맥스 2026-07-31은 그날 **+18.05%**(반등일)였고 07-30은 -1.35%였다. 52주 고점 대비 낙폭으로 걸면 발동이 14→6건으로 줄면서 07-30·07-31은 둘 다 남고, 2026-05-11(지수 **신고가**에서 반대매매 +2σ) 같은 중간 구간이 빠진다. -10%는 「기본 원칙 13」·전고점 낙폭 밴드와 같은 선이다 |
| `MARGIN_CALL_WINDOW_DAYS` | 120 | 이 스킬의 운영 선택. 250거래일은 `credit_balance`가 243행뿐이라 채워지지 않고, **60일 창은 폭락이 자기 σ를 부풀려** 임계를 끌어올린 탓에 2026-07-30·07-31 클라이맥스를 놓친다(시점 기준 백테스트 실측). 120일은 그 두 날을 잡는다 |
| 기준선 | **당일을 기준선에서 제외** | 오늘 값이 자기 평균·σ에 섞이면 값이 클수록 임계가 함께 올라가 정작 클라이맥스에서 신호가 무뎌진다 |

- 반대매매 분포는 오른쪽으로 크게 치우쳐 있어(평균 211억 · σ 271억) 정규분포의 +2σ보다 자주
  켜진다 — 낙폭 게이트 전 14일, 게이트 후 6일(직전 1년). **이 신호는 매수 트리거가 아니라 허용 조건이다.**
  「레버리지 규칙 2」의 방향성·업황 확인과 분할 진입은 그대로 요구된다.
- 성립한 날에는 「레버리지 규칙 3」이 발동 중이어도 지수 레버리지 **신규 매수**가 가능하다.
  **이미 들고 있는 레버리지를 어떻게 할지는 이 예외가 정하지 않는다 — 사용자 판단이다.**
- **판정은 KOSPI·KOSDAQ 각각 낸다.** 반대매매 금액은 시장 전체 하나지만 낙폭 국면이 지수마다
  다르고 레버리지 상품도 지수별이다. 실측(2025-01~2026-09)에서 KOSPI 게이트 8건 · KOSDAQ 게이트
  9건이고 겹치는 날은 3일(07-09·07-30·07-31)뿐이다.
- ⚠️ **검증 구간의 한계**: `credit_balance`는 한 번에 365행이 상한이고 최초 데이터가 2025-01-02라
  반대매매 조건은 **약 20개월(408거래일)까지만** 검증된다. 3년 검증은 불가능하다.
  지수 낙폭 조건만은 네이버 일봉으로 3.3년(800봉) 검증했다.

**지수 낙폭 사다리와 베팅 가능 구간** (2026-09-05 확정). 같은 스크립트가 함께 낸다.

- 「지수 낙폭 사다리」 줄 — KOSPI·KOSDAQ 각각 52주 고점 대비 낙폭을 **-10%부터 5%마다** 눈금으로
  찍고, 밟은 단·다음 단의 **지수 레벨**·남은 %p를 낸다. 다음 단 레벨을 미리 알아야 주문으로 옮긴다.
- `⚠️ 오늘 처음 밟은 단` 줄이 **분할 매수 행동 시점**이다. 매일 같은 단에 머무는 것은 사건이 아니다.
- 「레버리지 규칙 2」 줄이 `🟢 베팅 가능 구간`이면 **낙폭 -10% 이하 + 반대매매 +2σ**가 동시에
  성립한 날이다. 브리핑은 이 줄을 그대로 인용하고 재채점하지 않는다.

| 상수 | 값 | 근거 |
|---|---|---|
| `DRAWDOWN_RUNGS` | -10%부터 5% 간격 (~-60%) | 사용자 지정 (2026-09-05) |
| `RUNG_RECLAIM_DAYS` | 10 | 낙폭이 단 경계를 왕복하면 같은 단이 며칠 간격으로 되풀이 발동한다 — 실측에서 KOSPI -30%가 2026-07-28·08-03·08-06 세 번 울렸다. 직전 10거래일 안에 이미 밟은 단은 새 사건으로 세지 않는다 |

**깊은 단이 사실상 유일한 타이밍 신호다.** 3.3년·저점 18개 실측에서 얕은 단(-10/-15%)은 저점
100거래일 이상 전에 켜져 타이밍이 되지 못하지만, 2026-07-30 저점에서는 **KOSPI가 -30%를 T-2,
-35%를 T-1에**, KOSDAQ이 -40%를 T-2, -45%를 T-1에 처음 밟았다. 다만 -14% 수준에서 끝나는 얕은
저점은 깊은 단에 영영 닿지 않으므로 **이 신호는 큰 폭락에서만 타이밍 역할을 한다.**
T-2 예측은 원리적으로 불가능하다 — 저점의 상당수가 T-2→T0의 급락으로 만들어져서 T-2 시점에는
신호가 될 사건 자체가 없다(2024-08-05는 T-2에 낙폭 -3.9%, 2026-03-04는 T-2가 사상 최고가).

### 1-2단계: 변동성 지수 수집 (VKOSPI)

코스피 변동성 지수(VKOSPI, 코스피200 변동성지수 = 한국판 VIX)를 investing.com에서 가져온다.

사용 가능한 웹/브라우저 조회 기능을 사용한다. curl/스크립트 직접 요청은
Cloudflare 403으로 차단되므로 정상 수집 경로로 간주하지 않는다.

```
URL: `https://www.investing.com/indices/kospi-volatility`

현재값, 등락, 등락률, 일간 범위, 전일 종가, 52주 범위, 갱신 시각을 추출한다.
```

추출 항목: **현재가 · 전일대비(%) · 전일종가 · 일간범위 · 52주 범위 · 갱신시각**.

**빈 응답 대응 (필수)**:
1. URL `open` 결과가 빈 응답이면 곧바로 수집 실패로 판정하지 말고 같은 URL을 한 번 다시 연다.
2. 재시도도 비면 브라우저 검색에서 `Investing.com KOSPI Volatility` 결과를 찾고 해당 결과를 연다.
3. 텍스트 추출이 비어도 페이지 렌더링이 가능하면 브라우저 화면에서 위 추출 항목을 읽는다.
4. 당일 브리핑을 재생성·수정하는 경우 기존 당일 산출물이나 백업에 이미 수집된 값이 있는지 확인한다.
   값의 날짜와 출처가 같은 거래일임을 확인한 경우에만 재사용하고, 브리핑에 재사용 사실을 남긴다.
5. 각 단계의 실제 오류를 구분해 기록한다: HTTP 403, 빈 응답, 파싱 실패, 값 날짜 불일치.

웹 커넥터가 빈 본문을 반환하는 것은 지수 데이터 부재를 뜻하지 않는다. Investing.com 직접 HTTP
요청의 403도 예상된 차단이므로, 이를 우회하려고 curl 기반 수집기를 추가하지 않는다.

**해석 기준**:
- 절대 레벨 밴드 (평시): ~20 이하 안일 / 20~30 정상 / 30~40 경계 / 40 이상 공포
- **단, 절대 밴드만 쓰지 말 것.** 2026년 한국 증시는 VKOSPI 70~95 구간의 이상 국면이라
  절대 밴드가 무의미해질 수 있다. **52주 범위 내 위치**(`(현재-52주저)/(52주고-52주저)`)와
  **전일대비 방향**을 함께 판단 근거로 쓴다.
- 변동성 **급등**(전일比 +10% 이상) = 리스크 오프 가속 → 신규 진입 보류·포지션 축소 신호
- 변동성 **고점권에서 하락 전환** = 패닉 피크아웃 가능성 → 분할 매수 관찰 구간
- 지수는 오르는데 VKOSPI도 높음 = 양방향 급등락 국면 → 방향성 베팅보다 포지션 사이징 관리

**참고**: investing.com 값은 KRX 공식 VKOSPI와 스케일·수준이 일치하나 52주 고점 등 일부
수치는 미세 차이가 있을 수 있다. 사상 최고치 등 기록 수치를 인용할 때는 KRX 공식 기준을 쓴다.

- **실패 시**: 시장 상황 섹션에 "(VKOSPI 수집 실패)" 한 줄만 표기하고 나머지 단계는 정상 진행한다.
  이 단계 실패가 브리핑 생성을 블로킹해서는 안 된다.

### 1-3단계: 내 포트폴리오 로드 (Google Sheets)

보유 현황을 읽어 룰 판정과 실행 조언의 근거로 쓴다. **포트폴리오 표 자체는 브리핑에 넣지 않는다**
(반영 범위는 4단계 「포트폴리오 반영 범위」 참조).

1. **스냅샷 재사용**: `output/portfolio/<today>.md`가 있으면 그대로 읽고 2~4를 건너뛴다.
2. **파일 검색**: Google Drive 검색으로 스프레드시트를 찾는다. 파일 ID는 문서에 하드코딩하지 않는다.
   ```
   title = '주식 포트폴리오' and mimeType = 'application/vnd.google-apps.spreadsheet'
   ```
   `contains`가 아니라 **정확 일치**를 쓴다 (`주식 포트폴리오 통합본`이 함께 잡힌다).
3. **본문 받기 (CSV 내보내기)**: 위에서 얻은 `fileId`로 Drive `download_file_content`를
   `exportMimeType = text/csv`로 호출한다. 첫 시트(「포트폴리오」)만 CSV로 내려오고, 응답은
   `{"content": "<base64 CSV>", ...}` JSON이다. **이 JSON을 한 글자도 바꾸지 않고 그대로** 파일에
   저장한다(스크래치 디렉토리의 `portfolio_download.json` 등).
   - `read_file_content`는 쓰지 않는다 — 2026-09-28부터 셀 값을 `삼...`처럼 잘라 쓴 요약만 돌려줘
     파서가 읽을 수 없다.
   - ⚠️ 응답을 옮겨 적다 base64 끝이 잘리면 **마지막 보유 행이 통째로 빠진다**(2026-09-28 실제 사고:
     이수페타시스 200주가 「전량 청산」으로 읽혔다). 파서가 보유 행 평가금액 합계를 시트 잔고와
     대조해 0.5%(`BALANCE_TOLERANCE_PCT`) 넘게 어긋나면 exit 1로 거부하므로, 거부되면 추측으로
     메우지 말고 응답을 다시 받아 저장한다.
4. **파싱·저장**:
   ```bash
   uv run python .agents/skills/daily-digest/scripts/extract_portfolio.py \
       <CSV 응답 파일> --out output/portfolio/$(date +%Y-%m-%d).md
   ```
   입력은 CSV 내보내기 응답 JSON이 정본이고, 평문 CSV와 예전 `read_file_content` 덤프도 받는다.
   스크립트가 첫 시트(「포트폴리오」)의 보유 표·섹터 집계만 잘라내고,
   `context/my_rules.md` 임계값(-10 / -15 / -20 / 24~30 / 평가 비중 35% / 5~12종목)으로
   **룰 자동 판정**까지 계산한다. 임계 도달은 매도 이행 위반과 다르다. 이행 기록이나
   시장 급락 예외가 확인되지 않았으면 「도달 · 이행 확인 필요」로 인용한다.
   산술은 스크립트 출력을 그대로 인용하고 직접 재계산하지 않는다.
5. **전일 대비 비교**: 직전 스냅샷(`output/portfolio/`의 그 이전 날짜 파일)이 있으면 신규 편입·
   전량 청산·수량 변동 종목을 비교해 메모한다. 당일 매매가 있었으면 「의사 결정 조언」에서
   분할 매수/매도(매매규칙 4·5) 준수 여부를 함께 본다.
6. **실패 시**: 스냅샷 없이 진행하고 「의사 결정 조언」 머리에 "(포트폴리오 로드 실패)" 한 줄만
   남긴다. 이 단계 실패가 브리핑 생성을 블로킹해서는 안 된다.

### 1-3-1단계: 전고점 낙폭·계좌 MDD 판정

1-3단계 스냅샷이 있으면 이어서 실행한다. 스냅샷이 없으면 이 단계를 건너뛴다.

```bash
uv run python .agents/skills/daily-digest/scripts/peak_drawdown.py \
    output/portfolio/$(date +%Y-%m-%d).md --append
```

스크립트가 종목별 낙폭을 **두 축**으로 계산해 각각 -10 / -15 / -20 / -30% 밴드로 경보하고,
과거 스냅샷들의 잔고 최고치 대비 **계좌 MDD**까지 판정해 스냅샷 파일 끝에 「전고점 낙폭」
섹션을 덧붙인다(재실행하면 같은 섹션을 교체한다. 옛 제목으로 쓰인 섹션도 함께 걷어낸다).
산술은 스크립트 출력을 그대로 인용하고 직접 재계산하지 않는다.

| 축 | 고점의 정의 | 가격 기준 | 답하는 질문 |
|---|---|---|---|
| **52주 시장 고점** | 최근 250거래일 최고 종가 | StockEasy 정규장 일봉 **종가** (네이버 대체 시 섹션에 종목명과 꼬리표) | 이 종목이 시장에서 얼마나 밀렸나 |
| **계좌 기록 고점** | `output/portfolio/` 스냅샷에 기록된 최고 현재가 | 시트 **수집가** | 내 보유 구간에 얼마나 반납했나 |

**평단 기준 룰과 다른 축이다.** 「매매규칙 6」의 -15%(1차 분할)·-20%(전량)는 **평단** 기준이고
여기서의 -15%·-20%는 **고점** 기준이다. 숫자가 같아 섞기 쉬우므로 두 축을 같은 룰인 것처럼
쓰지 않는다 — 평단 축 판정은 1-3단계 스냅샷의 「룰 자동 판정」이 담당한다. 밴드별 대응(**두 축에 동일하게
적용되지만, 인용할 때는 어느 축에서 걸렸는지를 반드시 밝힌다**):

| 밴드 | 의미 | 연결 룰 |
|---|---|---|
| -10% | 관찰 — 추세 훼손 여부 점검 | 「기술적 분석 규칙 1(20주선)」 방향 확인 |
| -15% | trailing stop·추세 훼손 기준 재검토 | 「매매규칙 15」가 요구하는 사전 정의 기준을 실제로 적용 |
| -20% | 추세가 꺾였는지 판정 필요 | 「매매규칙 3(추세 기반 매도)」 · `stage-analysis` 재판정 권고 (3→4단계 의심) |
| -30% | 4단계 진입 의심 | 「매매규칙 5」 분할 매도 · 투자 아이디어 훼손 여부 확인 |

- **평단 수익률을 반드시 같이 읽는다.** 고점 대비 -30%인데 평단 대비 +100%면 손절 문제가
  아니라 **수익 쿠션·추세 훼손** 문제다 (「매매규칙 11」). 반대로 최근 편입 종목은 평단
  손실이 작아도 고점 낙폭이 클 수 있다 — 전고점이 매수 이전에 형성됐기 때문이므로
  경보를 그대로 손절 신호로 읽지 않는다.
- **두 축이 갈리면 그 자체가 정보다.** 52주 축만 깊으면 낙폭이 **내가 사기 전에** 생긴 것이고,
  계좌 기록 축까지 깊으면 **내 보유 구간에** 반납한 것이다. trailing stop이 실제로 걸리는
  자리는 후자에 가깝다. 두 축의 수치를 같은 룰 번호 아래 합산하거나 한 경보로 세지 않는다.
- **계좌 기록 축의 한계 3가지**: ① 스냅샷이 쌓인 구간 안에서만 고점을 찾으므로 그 이전 고점은
  반영되지 않는다(편입 직후 종목은 낙폭이 실제보다 작게 보인다) ② 시트 수집가는 장중·지연
  호가라 종가와 다를 수 있어 52주 축과 산술적으로 맞아떨어지지 않는다 ③ 매도 후 재매수 구간을
  구분하지 않고 전체 기록의 최고가를 쓴다. 각 수치의 유효 구간·스냅샷 개수는 섹션 각주에 찍힌다.
- **이 축은 네트워크를 쓰지 않는다.** 티커 미해석·시세 수집 실패로 52주 축이 비어도 계좌 기록
  축은 그대로 남으므로, 네이버가 죽은 날에도 낙폭 판정을 포기하지 않는다.

**종목 밴드도 밟기 전에 경고한다.** 두 축 각각에서 다음 밴드까지 **2.0%p 이내**로 들어온 종목을
`⚠️ 임박(축 이름)` 줄에 모아 **발동가를 금액으로** 찍는다(예: *대덕전자 -9.8% → -10% 발동가
₩101,430 (0.2%p 남음)*). 표의 경보 칸도 **발동 밴드가 없을 때만** `⚠️ -10%`로 임박을 보여준다 —
발동을 임박이 가리지 않는다. 「매매규칙 15」가 요구하는 trailing stop은 밴드를 밟은 뒤 정하면
이미 늦으므로, 발동가를 미리 알아야 주문으로 옮길 수 있다는 것이 이 경고의 목적이다.

- 마진은 `DRAWDOWN_WARN_MARGIN_PP`(기본 2.0%p, 계좌용 `ACCOUNT_MDD_WARN_MARGIN_PP`와 별도).
  밴드 간격이 종목(-10/-15/-20/-30)과 계좌(-10/-15)에서 다르므로 따로 조정할 수 있게 뒀다.
- 비교는 **표에 찍히는 소수 첫째 자리**로 반올림해서 한다. -12.969%는 표에 -13.0%로 나오고
  -15%까지 2.0%p로 읽히므로, 내부값 2.031%p를 이유로 경고를 빼면 출력끼리 어긋난다.
- 가장 깊은 밴드(-30%)까지 밟은 종목은 남은 경고가 없다. **계좌 기록 축의 임박은 스냅샷 표본이
  적은 종목(편입 직후)에서 신뢰도가 낮다** — 고점 자체가 짧은 구간의 값이기 때문이다.

**계좌 MDD는 밟기 전에 경고한다 (「기본 원칙 13」).** 잔고 고점 대비 -10% / -15% 발동선과 거기까지
남은 거리(%p·금액)를 **매일** 출력하고, 다음 밴드까지 **2.0%p 이내**로 들어오면 `⚠️⚠️ 계좌 MDD
-15% 임박` 경고와 함께 해당 밴드의 대응 문구를 같이 찍는다. -10%에서 요구하는 레버리지 정리·
현금 30% 확보, -15%에서 요구하는 5거래일 신규 매수 금지는 **밟은 뒤 준비하면 늦기 때문**이다.

- 경고 마진은 `ACCOUNT_MDD_WARN_MARGIN_PP`(기본 2.0%p), 대응 문구는 `ACCOUNT_MDD_ACTION`으로
  스크립트 상단에 있다. 「기본 원칙 13」 본문이 바뀌면 이 문구도 같이 고친다.
- 임박 경고가 뜬 날은 **「🛡️ 오늘의 룰 리마인드」에 「기본 원칙 13」을 최우선 채택**한다
  (발동 전이라도 채택한다 — 그게 경고의 목적이다).
- 이미 밟은 밴드는 임박 대상이 아니고(발동으로 표기), 가장 깊은 밴드까지 밟았으면 남은 경고가
  없다. 계좌 고점은 여전히 스냅샷 구간 기준이고 입출금을 보정하지 않는다.
- **티커 미해석** 종목이 보고되면 `context/ticker_overrides.md`에 `종목명 = 6자리티커`
  한 줄을 추가해 고정한다 (시트 표기가 정식 종목명과 다른 경우가 대부분이다).
- **실패 시**: 스크립트는 실패한 종목만 사유를 표기하고 exit 0으로 끝난다. 스냅샷 파싱
  실패(exit 1)일 때는 이 단계만 건너뛴다. **브리핑 생성을 블로킹하지 않는다.**

### 1-3-2단계: 보유 종목 매수·매도 트리거 점검

`output/watchlist/보유_트리거.md`가 있으면 **매일** 실행한다. 이 파일은 보유 종목별로 정해진 추가 매수
(증량 tranche·매수 금지 해제)와 추가 매도(사용자 확정 stop·추세 이탈선·익절 잔여·실적 훼손) 조건을 담는다.
`analyze-stock` 11단계와 「의사 결정 조언」에서 사용자가 확정한 대응이 등록한다. 파일이 없으면 건너뛴다.

1. 파일의 종목마다 `turn_scan.py <티커>`를 **순차로** 돌린다(병렬은 네이버 429). 조건에 스테이지·20주선이
   있으면 `stage_scan.py <티커>`도 돌린다. 가격 판정은 전부 **종가**다 — 장중 실행이면 「장중 · 미확정」으로 적는다.
2. 조건 하나하나를 스크립트 출력값과 대조해 ✅ / ❌와 **현재값**을 적는다. 모델이 차트를 눈대중해 채우지 않는다.
   이벤트 조건(실적·공시)은 오늘 raw·StockEasy 뉴스에 그 사실이 나왔는지로 판정하고, 없으면 ⏳.
3. 결과는 「의사 결정 조언」에 **매도 먼저, 매수 다음**으로 종목별 한 줄씩 넣는다:
   - 매도 조건 충족 → `🔴 매도 트리거 발동 — <조건> · <수량>주`. 그날 룰 리마인드에 해당 룰(「매매규칙 3·5·6·11·15」)을 최우선 채택한다.
   - 매수 조건 전부 충족 → `🟢 매수 조건 충족 — <tranche> <수량>주` + "`analyze-stock` 승계 실행으로 손익비 재확인 후 집행".
     룰 리마인드에 「매매규칙 4(분할 매수)」를 채택한다.
   - 미충족 → `🟡 대기 — 남은 조건: …` (가장 가까운 가격선까지 %·원).
   - 폐기 조건 충족 → `⛔ 계획 폐기` + 파일 해당 항목에 폐기일을 적는다.
   - 파일에 없는 보유 종목은 쓰지 않는다 — 개별 트리거 미정은 스킵이다.
4. 가격선마다 파일에 적힌 **기준일**을 본다. 10거래일이 지났거나 새 리포트·실적이 나왔으면 "가격선 재산정 필요"를 함께 적는다.
5. 보유 수량이 스냅샷과 달라졌으면(매매 발생) 해당 항목의 수량·평단·잔여 수량을 스냅샷 값으로 고친다.
   전량 매도된 종목은 항목을 지운다.
6. 실패한 종목은 `미수집 — <사유>` 한 줄. 브리핑 생성을 블로킹하지 않는다.

### 1-4단계: 이미지 판독 (OCR·차트 해석)

raw 파일에는 텔레그램 첨부 이미지가 `이미지:` 블록으로 들어 있다. `fetch-messages`는
파일을 `output/daily-digest/media/<today>/`에 내려받고 판독은 하지 않으므로, 여기서
이미지를 직접 보고 텍스트와 차트 해석을 raw 파일에 적어 넣는다. 이 단계를 건너뛰면
2단계 분류가 이미지에만 있는 정보(차트 캡처, 공시 캡처, 표)를 통째로 놓친다.

**1) 판독 대상 수집**

```bash
grep -an "\[분석 대기\]" -B 1 output/daily-digest/raw/<today>_raw.md
```

- **`-a` 필수.** 링크 본문이 raw에 들어가던 2026-09-10 이전의 raw에는 PDF 링크 본문의
  NUL 바이트가 섞여 있어, `-a` 없이는 grep이 바이너리로 보고 아무것도 내놓지 않는다.
- 0건이면 이 단계 전체를 건너뛰고 그 사실만 알린다.
- `> 파일:` 줄에 적힌 경로가 판독 대상이다. `[이미지 저장 실패:` / `[이미지 건너뜀:`
  으로 시작하는 줄은 파일 자체가 없으므로 대상이 아니다.

**2) 판독**

각 이미지를 **파일 읽기 툴로 직접 읽는다** (증권사 리포트 PDF를 파일 읽기 툴로 읽는
`analyze-stock` 4단계와 같은 방식이다. 로컬 OCR 도구를 설치하거나 호출하지 않는다).

**3) raw 파일에 기록**

해당 이미지의 `> [분석 대기]` 줄을 아래 블록으로 **치환**한다:

```
> 유형: 차트 | 표 | 뉴스 캡처 | 공시 캡처 | 기타
> 텍스트: (이미지에 적힌 한글·영문·숫자를 그대로. 없으면 "없음")
> 해석: (차트면 축·계열·추세 방향·핵심 수치·변곡점, 표면 행·열 요지. 3-5줄)
```

- 판독 실패 시 `> [이미지 판독 실패]`로 치환한다.
- **보이는 것만 쓴다.** 축 라벨 없는 그래프에 수치를 지어내지 않는다 — 「주의사항」의
  "추측 금지"가 이미지에도 그대로 적용된다. 차트에서 읽은 값이 대략치면 대략치라고 쓴다.
- **멱등**: `[분석 대기]`로 남은 항목만 처리하므로 재실행해도 이미 판독한 블록은
  건드리지 않는다.

**실패 시**: 판독이 안 된 이미지는 2단계에서 캡션·맥락만으로 판단하고 `(이미지 미확인)`
으로 표기한다. **브리핑 생성을 블로킹하지 않는다.**

### 1-5단계: 링크 본문 요약

링크 본문은 길어서, raw에 들어가면 2단계 이후 브리핑을 쓰는 컨텍스트를 채운다. 그래서
`fetch-messages`는 읽기에 성공한 링크 본문을 전부 `output/daily-digest/links/<today>/`에 파일로
저장하고(네이버 블로그 글은 `<블로그ID>_<글번호>.md`, 나머지는 `<도메인>_<URL 해시>.md`, 본문이
PDF면 같은 이름의 `.pdf`), raw 링크 블록에는 URL·`> 파일:` 경로·`> [요약 대기]`만 남긴다. 읽기에
실패한 링크는 실패 표시가 raw에 그대로 남고, 로그인해야 보이는 페이지는 `[건너뜀: 로그인 필요]`로
받지도 않는다. 증권사 리포트 링크(StreamDocs 뷰어·한투 `download_pdf.jsp`·`.pdf` 직링크)는 PDF
원본으로, DART 공시 주소는 틀이 아닌 공시 본문으로 저장된다 — 수집 경로는 `market-data` 스킬 참조. **메인 에이전트는 요약이 raw에 반영된 뒤의 raw만 읽는다 — 원문 파일과 요약 파일은
서브에이전트와 스크립트가 다룬다.**

**1) 대상 수집**

```bash
grep -an "\[요약 대기\]" -B 1 output/daily-digest/raw/<today>_raw.md
```

- 0건이면 이 단계 전체를 건너뛰고 그 사실만 알린다.
- 마커 바로 윗줄의 `> 파일:` 경로가 요약 대상이다.

**2) 서브에이전트에 나눠 요약**

대상 파일을 **8개씩** 묶어, 묶음마다 서브에이전트 하나를 **병렬로** 띄운다(Claude Code는 한 응답에서
`Agent` 도구의 general-purpose 에이전트를 여러 개, Codex는 서브에이전트 기능). 서브에이전트가 쓰는
파일은 **원문 옆 요약 파일**(`X.md`·`X.pdf` → `X.summary.md`)뿐이다 — 저마다 자기 파일만 쓰므로 병렬이어도
서로 덮지 않는다. 넘길 지시는 아래 그대로 쓰고 파일 목록만 채운다:

```
아래 파일은 링크 본문 원문이다(뉴스·리포트·공시·블로그 글 등). 파일마다 읽고, 같은 폴더에
이름 끝의 확장자(`.md` 또는 `.pdf`)를 `.summary.md`로 바꾼 파일을 만들어 아래 형식의 요약을 쓴다.
네가 쓰는 파일은 이 요약 파일들뿐이다. `.pdf`는 증권사 리포트 원본이다 — 파일 읽기 툴로 앞
1~5쪽만 읽는다(요약·투자의견·목표주가·핵심 추정치가 앞에 있다). 로컬 PDF 도구는 쓰지 않는다.

요약: {출처·필자} 「{제목}」
- 핵심: {주장·사실} (3~6개, 한 줄씩)
- 단서: {필자가 단 조건·반대 논거·불확실성. 없으면 "없음"}
- 결론: {한 줄}

규칙: 1,000자 이내이고 원문보다 길게 쓰지 않는다 — 원문이 몇 줄뿐이면 핵심 1~2개로 끝낸다.
종목명·수치·날짜는 원문 표기 그대로 옮기고, 원문에 있는 것만 쓴다. 필자의 단서와 반대 논거를
반드시 남긴다 — 요약에서 가장 먼저 사라지는 부분이다. 원문이 깨진 바이트·로그인 안내처럼 읽을 글이
아니거나 요약에 실패하면 요약 파일에 `[요약 실패]` 한 줄만 쓴다.
반환은 "처리 N건 / 실패: {경로 목록}" 한 줄.

파일 목록:
- output/daily-digest/links/<today>/...
```

**3) raw에 반영**

```bash
uv run python .agents/skills/daily-digest/scripts/apply_link_summaries.py \
    output/daily-digest/raw/<today>_raw.md
```

스크립트가 각 `> [요약 대기]`를 옆 요약 파일 내용(줄마다 `> `)으로 치환하고, `반영 N건 · 대기 M건`과
아직 요약 파일이 없는 원문 경로만 출력한다. 요약 내용은 출력하지 않는다.

- **완료 기준**: `대기 0건`. 대기가 남으면 그 파일만 2)를 다시 위임하고 3)을 다시 돌린다.
- 위임 수단이 없는 클라이언트는 한 편씩 원문을 읽고 같은 형식으로 요약 파일을 쓴 뒤 3)을 돌리고,
  이후 단계에서는 raw의 요약만 인용한다.
- **멱등**: 스크립트는 `[요약 대기]`로 남은 항목만 처리하므로 재실행해도 이미 반영된 블록은 건드리지 않는다.

**실패 시**: `[요약 실패]`인 링크는 2단계에서 제목·맥락만으로 판단하고 `(링크 미확인)`으로 표기한다.
**브리핑 생성을 블로킹하지 않는다.**

### 2단계: 메시지 분류 및 인사이트 추출

**raw 파일 읽기 방법 (대용량 파일 대응)**

raw 파일은 수천 줄에 달할 수 있으므로 한 번에 읽지 말고 청크 단위로 나눠 읽는다:

```
파일 읽기 기능이나 `sed`를 사용해 200줄 이하의 범위로 순차 조회한다.
```

- `limit`은 200줄 이하로 유지한다 (토큰 초과 오류 방지)
- 각 청크를 읽을 때마다 분류에 해당하는 내용을 즉시 메모해두고, 다음 청크로 넘어간다
- 파일 끝은 청크가 비어있거나 오류가 날 때 확인된다
- 모든 청크를 읽은 후 메모한 내용을 종합해 섹터/종목별로 정리한다

raw 파일 전체를 읽은 뒤 다음 기준으로 분류한다:

**분류 우선순위:**
1. **종목 언급**: 종목 이름이 직접 언급된 메시지
2. **섹터 관련**: 특정 섹터(반도체, 바이오, 소비재 등)에 해당하는 리포트/뉴스
3. **사용자 작성 메모**: 메모, 반성, 시황, 개인 의견 등
4. **매크로/시장 전반**: 금리, 환율, 지정학, 미국 증시 등 시장 전반 이슈

**각 종목/섹터에 대해 추출할 내용:**
- 핵심 인사이트: 투자 판단에 직결되는 내용 (증권사, 목표주가 변경, 실적 전망, 업황 변화 등)
- 원문 요약: 포워드/뉴스/리포트 내용을 1-3문장으로 압축
- 투자 시사점: 투자 의사 결정에 도움이 되는 핵심 인사이트 및 조언

**판단 기준:**
- 실적/매출 데이터 ATH(역대 최고)는 강한 모멘텀 신호로 적극 반영
- 증권사 리포트의 목표주가 상향/하향은 컨센서스 변화로 별도 표기
- 내부자 매수는 신뢰도 높은 신호로 강조
- 링크 읽기 타임아웃된 항목은 제목/맥락만으로 판단하고 "(링크 미확인)" 표기
- 1-4단계에서 판독한 `이미지:` 블록은 본문 텍스트와 **동급**으로 분류에 쓴다. 다만
  차트 이미지에서 읽은 수치·추세는 출처를 `(이미지)`로 표기해 원문 텍스트와 구분한다.
  판독 실패한 이미지는 캡션·맥락만으로 판단하고 "(이미지 미확인)" 표기
- 1-5단계의 `요약:` 블록은 본문 텍스트와 **동급**으로 분류에 쓰고 출처를 `(링크 요약)`으로
  표기한다. 특정 수치를 원문에서 확인해야 할 때만 링크 원문 파일을 `grep`으로 찾아 그 줄만 본다

### 2-1단계: 오늘의 중요도 표시(🔥) 선별

분류 끝낸 뒤 오늘 raw에서 **가장 임팩트 큰 1~2개**(최대 3개)를 고른다. 별도 섹션을 만들지 않고
**「📂 섹터별 / 종목별 정리」 본문의 해당 항목 종목명 앞에 `🔥`를 붙인다.**

브리핑 위쪽의 압축 섹션은 2026-09-21에 없앴다 — **상단 압축 → 섹터별 정리는 같은 내용을 두 번 쓰는
구조**였고(2026-09-09에 그 사이의 요약 섹션을 한 겹 걷어낸 것과 같은 이유), 압축본과 전문이 따로
있으면 둘이 어긋날 때 어느 쪽이 정본인지도 정해지지 않는다. 중요도는 **정보가 있는 그 자리에서**
표시한다.

**선별 기준 (우선순위)**:
1. 메가 이벤트: 정책 전환, 매크로 충격, 슈퍼사이클 신호
2. 컨센 점프: 다수 증권사 동시 목표가 상향/하향, 어닝 서프 큰 폭
3. 구조 변화: 신규 공급계약, 신시장 진입, 빅파마 딜, 표준 채택
4. 가격 액션: 거래량 동반 ATH 돌파, 섹터 동시 급등

**표기 규칙**:
- `🔥`는 **종목명 앞에만** 붙인다. 하위 불릿에는 붙이지 않는다.
- 🔥를 붙인 항목은 **사실 근거와 시사점(왜 중요한가)을 반드시 함께** 쓴다. 나머지 항목보다 한 줄 더
  들어가는 것이 🔥의 값이다.
- **하루 3개를 넘기지 않는다.** 전부 중요하면 아무것도 중요하지 않다.
- **단순 주가 변동만으로는 🔥를 붙이지 않는다.** 주가·수급은 「🚦 시장 상황」 전담이다.
- ⛔ **브리핑 본문에 `⭐`를 쓰지 않는다 (2026-09-21 사용자 결정).** 누적 컨텍스트(3·6단계)가
  `⭐`/`⭐⭐`를 **테마의 진척 강도**로 이미 쓰고 있어, 같은 기호를 브리핑의 **오늘 중요도**에 쓰면
  두 층이 한 화면에서 구분되지 않는다. 기호를 나눈 것이 구분의 전부이므로 되돌리지 않는다.
  ⚠️ 두 층은 자동으로 이어지지도 않는다 — 브리핑의 🔥가 그대로 누적 항목이 되지는 않고,
  6단계의 반복성·구조성 필터를 따로 통과해야 ⭐가 붙는다.

### 3단계: 월간 누적 컨텍스트 로드

매일 브리핑은 reset이지만 한 달 동안의 핵심 흐름은 별도 누적 파일에 보관한다. 누적 컨텍스트는
**2단 구조**다 (2026-08-09 개편 — 단일 파일이 302KB까지 커져 한 번에 읽을 수 없게 된 문제 대응):

```
output/daily-digest/monthly_context.md          # 인덱스: 항목당 1줄 (~62KB, 1회 Read 가능)
output/daily-digest/themes/<slug>.md            # 테마 전문 (파일당 ≤40KB)
output/daily-digest/themes/archive/<slug>-<from>~<to>.md   # 30일 경과분
```

**읽기 순서 (필수)**:

1. **인덱스 `monthly_context.md`는 항상 전체를 읽는다.** 파일 상단의 「읽기 프로토콜」 섹션이 최신 규칙.
2. 인덱스 항목에 `→ [[themes/<slug>]]` 포인터가 있으면 전문이 별도 파일에 있다.
   **오늘 raw와 직접 겹치는 테마만 열어 읽는다. 전부 열면 컨텍스트가 고갈된다.**
3. 포인터 없는 항목은 인덱스 안에 원문 그대로 있다(경량 항목).
4. `themes/archive/`는 특정 과거 사실 확인이 필요할 때만 읽는다.

**조언/인사이트 작성 전 반드시 인덱스를 먼저 읽는다.** 구조 인식이 단일 일자보다 훨씬 강력하다.

이 컨텍스트가 담는 것:
- **반복 등장 신호**: 여러 날 걸쳐 같은 종목/섹터/매크로 이슈가 누적되는 패턴
- **메가 트렌드 트랙킹**: 진행 중인 슈퍼사이클·정책·지정학 흐름의 진척도
- **주요 이벤트 캘린더**: 학회·실적 발표·만기 이벤트 등 향후 트리거
- **컨센 변화 누적**: 한 종목/섹터에 대한 증권사 시각 변천

파일이 없으면 빈 상태로 시작.

**⚠️ 절대 하지 말 것**: 인덱스나 테마 파일을 `cut -c1-N` 등으로 잘라 읽고 조언을 쓰는 것.
잘라 읽으면 제목만 보고 본문을 못 본 상태가 된다. 크기가 문제면 자르지 말고
**아래 6단계 쓰기 규칙에 따라 파일을 분리**한다.

### 4단계: 투자 조언 생성

`../advice/SKILL.md`의 방법론을 참조한다.

**나만의 규칙 참조 (필수)**: 「의사 결정 조언」 섹션과 투자 조언 작성 전에
저장소 루트 기준 `context/my_rules.md`를 **반드시 읽고** 참고하며,
조언이 규칙과 관련되면 해당 룰을 번호·원문 그대로 명시적으로 인용한다.

**🛡️ 오늘의 룰 리마인드 (브리핑 최상단, 필수)**: 브리핑 문서의 **가장 맨 위**
(제목 바로 아래, 「🚦 시장 상황」보다 먼저)에 `context/my_rules.md`의 룰 중 **그 날의
시장 상황에 가장 적절한 항목 1~2개**를 채택해 리마인드 섹션으로 넣는다.

- **포트폴리오 룰 판정 우선**: 1-3단계 스냅샷의 「룰 자동 판정」과 1-3-1단계 「전고점 낙폭」에
  **위반·발동 항목이 있으면 그 룰을 최우선 채택**한다 (예: 평단 -15%/-20% 초과 보유 종목 → 매매규칙 6,
  비중 30% 근접 → 매매규칙 9, 24~30%↑ 수익 종목 → 매매규칙 11, **계좌 MDD -10%/-15% 도달
  또는 임박(⚠️⚠️ 경고) → 기본 원칙 13**, 전고점 -20%↓ 종목 → 매매규칙 3·15 — **52주 축이든
  계좌 기록 축이든 발동하면 대상이며, 어느 축에서 걸렸는지를 함께 적는다**). 걸린 항목이
  없을 때만 아래 시장 상황 기준으로 고른다.
- 선택 기준 예시:
  - 지수 낙폭 사다리에서 **오늘 처음 밟은 단**이 나오면 → 「레버리지 규칙 2」 분할 진입 검토 +
    「기본 원칙 8(풍림화산)」. 사다리 줄과 다음 단 지수 레벨을 함께 인용한다
  - `🟢 베팅 가능 구간`이 뜨면 → 「레버리지 규칙 2」를 최우선 채택하고, 지수별 판정과
    낙폭·반대매매 수치를 그대로 옮긴다. **기존 보유 레버리지 처리는 사용자 판단이라고 명시한다**
  - 지수 급락/급등·왕복 변동성 → 「레버리지 규칙 3」. **판정은 1-1단계 `fetch_market_signals.py`의
    `[레버리지 규칙 3]` 줄이 확정한다 — 재채점하지 말고 인용한다.** 발동(⛔)이면 그 줄을 그대로
    옮기고 레버리지 전량 정리·신규 진입 금지를 조언에 건다. 섹터 레버리지는 판정 대상이 아니다
  - 보유 종목 급락 언급 → 매매규칙 7 (-10% 비중 축소 고려·물타기 금지), 매매규칙 6 (-15% 1차 분할 매도 → -20% 전량 매도)
  - 보유 종목이 고점에서 꺾임(전고점 낙폭 발동) → 매매규칙 3 (추세 기반 매도), 매매규칙 15 (trailing stop 사전 설정)
  - 계좌 잔고가 직전 고점에서 밀림 → 「기본 원칙 13」 (계좌 MDD -10%/-15% 대응)
  - 급등주 추격 욕구·신규 진입 검토 → 「기본 원칙 4」 (2%룰 포지션 사이징), 매매규칙 12 (장대 양봉 매수 금지)
  - 보유 종목 큰 수익 구간 → 매매규칙 11 (24~30% 수익 시 보유량 10~30% 익절), 매매규칙 5 (분할 매도)
- 형식: 룰 원문 인용 + 오늘 상황에 왜 이 룰인지 1줄 연결. 3줄 이내로 짧게.

**포트폴리오 반영 범위 (필수)**:

원점 사고는 "포트를 보지 마라"가 아니라 **"평단에 앵커링하지 마라"**다. 「기본 원칙 6」 「오늘이 원금」
자체가 "지금 현금 100%라면 현재의 포트대로 구성할지" 를 묻기 때문에 포트를 알아야 판정된다.
섹션별로 반영 범위를 나눈다:

| 섹션 | 포트 반영 |
|---|---|
| 「💡 오늘의 투자 조언」 3관점(가치/차트/매크로) | **금지 — zero-base 유지** |
| 「🛡️ 오늘의 룰 리마인드」 | **필수** — 스냅샷 룰 판정·전고점 낙폭에서 걸린 항목 우선 |
| 「의사 결정 조언」 | **필수** — 보유 종목 수량·평단·비중 기준 실행 조언 |

**zero-base 구간 규칙 (3관점 조언)**:
- **보유 여부로 유불리를 판단하지 않는다.** "내 포트에 있어서 좋다/없어서 안타깝다" 관점 금지.
- **오늘 처음 시장을 보는 신규 투자자 관점**으로 작성한다. "지금 신규 진입할 만한가?", "지금 매도가 합리적인가?" 같은 zero-base 질문에 답한다.
- 보유 종목이 추천에서 누락돼도 문제 없음. 보유 종목이 부정적 신호 받아도 그대로 표기.
- 농구천재 인용 원칙: "오늘 현금 100이라면 이 비중이 맞나?"

**포트 인지 구간 규칙 (룰 리마인드 · 의사 결정 조언)**:
- 스냅샷의 종목명·수량·평단·비중·수익률을 **구체 수치로 인용**한다 (손절선·익절선은 실제 가격 환산).
- 오늘 raw에 나온 이슈가 보유 종목과 겹치면 그 종목의 현재 비중·손익 구간과 연결해 실행 조언을 만든다.
- 포트폴리오 표 전체를 브리핑에 붙여넣지 않는다. 조언에 필요한 항목만 인용한다.

오늘 메시지 + 월간 누적 컨텍스트에서 포착된 **가장 중요한 1-2개 테마**를 골라 세 관점에서 조언:

- **가치투자 관점**: 버핏/멍거/린치 시각으로 내재가치, 해자, 안전마진 관점
- **차트·추세 관점**: 미너비니/오닐 기준으로 스테이지, 진입/손절 조건
- **매크로 관점**: 드루켄밀러/소로스 시각으로 금리/유동성/자금 흐름

상세 방법론 파일도 참조할 수 있다:
- `../advice/references/value_investing.md`
- `../advice/references/trend_following.md`
- `../advice/references/macro.md`
- `../advice/references/second_level_thinking.md` — 막스 2차적 사고·사이클 위치 (「기본 원칙 12」 대응)
- `../advice/references/aphorisms.md` — 상황에 맞는 격언 2-3개 선별

### 5단계: 브리핑 파일 저장

`template/daily_digest.md` 템플릿 구조를 따라 브리핑을 작성하고 **월별 서브 디렉토리** 아래에 저장한다:

```
output/daily-digest/<yyyy-mm>/<yyyy-mm-dd>.md
```

예: 오늘이 2026-05-08이면 → `output/daily-digest/2026-05/2026-05-08.md`

월 디렉토리가 없으면 먼저 생성한다 (`mkdir -p`). 날짜는 오늘 날짜 (`_raw.md` 파일명과 동일한 날짜).

### 6단계: 월간 누적 컨텍스트 갱신

브리핑 저장 후 누적 컨텍스트를 갱신한다. **쓰기 대상은 원칙적으로 테마 파일이고, 인덱스는 요약만 고친다.**

**⛔ 수급 전용 항목은 누적하지 않는다 (2026-08-09 사용자 지시)**

핵심 근거가 **매일 새로 수집되는 데이터**인 항목은 누적 컨텍스트에 넣지 않는다. 1-1단계(StockEasy)와
1-2단계(VKOSPI)에서 매일 최신값을 받으므로, 누적해도 낡은 숫자만 남는다.

| 제외 (누적 금지) | 유지 (누적 대상) |
|---|---|
| 지수 등락·폭락 일지, FTD·분산일 카운트 | 실적·수주·계약·가이던스 |
| 신용잔고·예탁금·반대매매 추이 | 임상·허가·특허 진척 |
| breadth(20/200일선 하회·ADR·52주 신고저) | 정책·제도·규제 변화 |
| VKOSPI 등 변동성 수치 | 기술·표준·점유율 구조 변화 |
| 일별 ETF 자금 유출입 | 내부자 매수·오버행 일정 |

- 수급 데이터는 **그날 브리핑의 「🚦 시장 상황」 섹션에만** 쓴다.
- 단, **매일 갱신되지 않는 구조적 수급 인프라**는 유지한다 (예: IBKR 직매수 인프라, 국민성장펀드·
  커버드콜 ETF 규모, 레버리지 ETF가 조정 패턴을 바꿨다는 인식 프레임).
- 판단 기준 한 줄: **"내일 다시 수집하면 이 숫자가 바뀌는가?"** → 바뀌면 누적 금지.
- 기존에 누적된 수급 항목은 `themes/archive/flow/`로 격리한다 (삭제 아님, 인덱스에서만 제외).

**갱신 룰**:
- 2-1단계에서 **🔥를 붙인 항목 중 반복성·구조성** 있는 것만 추가 (단발 이벤트는 스킵).
  🔥는 「오늘 중요했다」는 표시일 뿐이므로 그대로 누적하지 않는다 — 이 필터를 따로 통과해야
  누적 쪽 기호(⭐/⭐⭐)가 붙는다. **두 기호를 서로 옮겨 적지 않는다**
- **수급 전용 항목은 위 표 기준으로 제외**
- 기존 항목 중 오늘 진척이 있으면 **해당 테마 파일에 일자 서브불릿을 추가**하고,
  인덱스 그 항목의 `최근(YYYY-MM-DD): …` 부분만 새 내용으로 교체
- 신규 테마는 인덱스에 1줄 추가 + `themes/<slug>.md` 생성 (슬러그는 한글 허용, 이모지·괄호 제거)
- 이미 종료된 이벤트(실적 발표 끝, 학회 종료, 트렌드 소멸)는 제거
- 30일 경과 + 후속 신호 없는 항목 제거

**중복·오염 방지 룰 (2026-08-09 정리에서 도출)**:
- **중복 금지**: 같은 종목·테마가 두 항목으로 갈라지면 즉시 하나로 통합한다. 하위 내용은 새 항목을
  만들지 말고 **테마 파일 안의 섹션**으로 넣는다. (예: 디앤디파마텍 8/5 + 5/27 → 파일 1개)
- **완료 이벤트 처리**: 캘린더에서 지나간 항목은 `~~취소선~~ + 결과` 형태로 남기지 않는다.
  **결과 1줄을 해당 테마 파일에 옮기고 캘린더에서는 삭제**한다. 캘린더는 미래만 담는다.
- **'의향·추진' 단계에서 진척 없는 항목 제거**: 본계약·공시로 격상되지 않고 30일 지나면 소음이다.
- **반복 등장 신호 유지 기준 (셋 중 하나도 없으면 제거)**: ① 최근 2주 내 신규·업데이트
  ② 향후 트리거가 날짜로 특정됨 ③ 재사용되는 판단 프레임(회피 필터·룰 판정 등).
- **2027년 이후 이벤트**는 개별 항목으로 두지 않고 「2027 이후」 묶음 1~2줄로 압축한다.

**크기 규칙 (필수 — 위반 시 다음 세션이 파일을 읽지 못한다)**:

| 대상 | 상한 | 초과 시 조치 |
|---|---|---|
| 인덱스 항목 1줄 | 400자 | 전문을 테마 파일로 옮기고 인덱스는 요약만 남긴다 |
| 인덱스 파일 전체 | 80KB | 경량 항목까지 테마 파일로 분리 |
| 테마 파일 1개 | 60KB (1회 Read 한계 ≈ 25k 토큰) | 30일 경과 서브불릿을 `themes/archive/<slug>-<from>~<to>.md`로 롤오프 |
| 테마 파일 내 서브불릿 | 최근 30일분 | 그 이전은 아카이브로 롤오프 + 상위 파일에 포인터 1줄 남김 |

30일분만 남겨도 60KB를 넘는 초대형 테마(예: AI 메모리 슈퍼사이클)는 **보존 창을 21일 → 14일로
좁혀** 추가 롤오프한다. 파일을 자르지 말고 창을 좁히는 것이 원칙이다.

갱신 후 인덱스와 수정한 테마 파일 크기를 확인한다 (`wc -c`). 상한을 넘겼으면 그 자리에서 분리한다.

**구조**:

### 7단계: 과거 raw·미디어 정리

브리핑·월간 컨텍스트 저장이 모두 끝나면 오늘자 raw·미디어·링크 원문만 남기고 과거 파일을
삭제한다. raw와 내려받은 이미지·링크 원문은 일회성 원본이라 누적할 이유 없음 — 판독·요약
결과는 이미 raw를 거쳐 브리핑·월간 컨텍스트에 텍스트로 남았다.

**선행 조건 (안전장치)** — 둘 다 충족해야 정리 진행. 하나라도 없으면 스킵 + 사유 알림:
- 오늘 브리핑 `output/daily-digest/{yyyy-mm}/{today}.md` 존재 확인 (월별 서브 디렉토리 안)
- 오늘 raw `output/daily-digest/raw/{today}_raw.md` 존재 확인

**삭제 명령**:
```bash
TODAY=$(date +%Y-%m-%d)
find output/daily-digest/raw \
     -maxdepth 1 -type f -name '*_raw.md' \
     ! -name "${TODAY}_raw.md" -print -delete
find output/daily-digest/media \
     -mindepth 1 -maxdepth 1 -type d \
     ! -name "${TODAY}" -print -exec rm -rf {} +
find output/daily-digest/links \
     -mindepth 1 -maxdepth 1 -type d \
     ! -name "${TODAY}" -print -exec rm -rf {} +
```

- 저장소 루트에서 `output/daily-digest/raw` 상대 경로를 사용한다.
- **사용자 승인을 기다리지 않고 바로 삭제한다** (2026-08-07 사용자 지시). 선행
  조건 2개만 충족하면 확인 질문 없이 `-delete`를 실행하고, 삭제된 경로를 사후
  보고한다. 선행 조건이 하나라도 미충족이면 삭제하지 않고 사유만 알린다.
- `-maxdepth 1`: 서브디렉토리 건드리지 않음
- `! -name "${TODAY}_raw.md"`: 오늘자 보존
- `-print -delete`: 삭제 경로 출력
- 미디어·링크 원문은 날짜별 **디렉토리**라 `-type d` + `rm -rf`를 쓴다. `media`나 `links`
  디렉토리가 아직 없으면 `find`가 에러를 내는데, 받은 이미지·링크가 없었다는 뜻이므로 무시하고 진행한다.

**보존 대상 (절대 삭제 금지)**:
- `output/daily-digest/raw/{today}_raw.md`
- `output/daily-digest/media/{today}/**` (오늘 내려받은 이미지)
- `output/daily-digest/links/{today}/**` (오늘 받은 링크 원문과 요약 파일)
- `output/daily-digest/{yyyy-mm}/{YYYY-MM-DD}.md` (월별 서브 디렉토리 안 브리핑 — raw 디렉토리 밖, 자동 보존)
- `output/daily-digest/monthly_context.md` (인덱스, 자동 보존)
- `output/daily-digest/themes/**` (테마 전문·아카이브, raw 디렉토리 밖 — 자동 보존)
- `output/portfolio/**` (포트폴리오 스냅샷 — raw 디렉토리 밖, 전일 대비 비교용으로 삭제하지 않는다)

**사용자 보고**: 삭제된 파일 수, 보존된 오늘 raw 경로 출력.

## 보조 도구 — 스냅샷 간 수량 변화

**`scripts/portfolio_diff.py`** — 어제 스냅샷과 오늘 스냅샷 사이의 **보유 수량 변화**를 구조화한다.
"어제 200주 → 오늘 100주"까지가 이 도구의 답이고, 그것을 매도로 부르지 않는다. 매매·입출금·
기업행위는 `--events`로 사용자가 준 것만 태그로 붙는다. 수량이 준 이유를 추정해 브리핑에 적으면
액면분할이나 이관을 매도로 기록하게 된다.

```bash
uv run python .agents/skills/daily-digest/scripts/portfolio_diff.py \
  output/portfolio/<어제>.md output/portfolio/<오늘>.md \
  [--events <이벤트.json>] [--run-manifest <매니페스트.json>] [--json]
```

- 1-3단계에서 오늘 스냅샷을 만든 뒤에 돌린다. 변화가 없으면 출력도 비어 있다.
- 변화가 있는데 사용자가 준 이벤트로 설명되지 않으면, 브리핑에 **사실만** 적고 사유는 되묻는다.

## 출력 품질 기준

섹션별 슬롯·분량은 `template/daily_digest.md`가 정본이다. 여기는 템플릿이 규정하지 않는
**내용 품질 기준**만 정의한다.

- **섹션 경계 (중복 방지 핵심 룰)**
  - **시황성 = 「🚦 시장 상황」 전담**: 지수·개별 주가 급등락, 거래대금, 외인/기관 수급,
    섹터 로테이션, 변동성 국면(VKOSPI 수준·방향)과 대응 스탠스. 수치 나열로 끝내지 말고
    **한줄 판단**까지 도출한다
  - **내용성 = 「📂 섹터별 / 종목별 정리」 전담**: 실적·수주·정책·기술·컨센 변화 등 무슨 이슈가
    있었는지. 주가 변동·수급 문장을 여기 다시 쓰지 않는다. **브리핑 위쪽에 압축·요약 섹션을 따로
    두지 않는다** (요약 섹션 2026-09-09 제거 → 상단 압축 섹션 2026-09-21 제거) — 같은 내용을 위에
    한 겹씩 더 쌓으면 두 번·세 번 쓰게 되고 압축본과 전문이 어긋날 때 정본도 정해지지 않는다.
    **그날의 중요도는 2-1단계의 `🔥`로 이 섹션 안에서 표시한다**
- **인사이트**는 "무슨 일이 있었다"가 아니라 "그게 왜 중요한가"에 답해야 한다
- **투자 조언**은 오늘 메시지 + 월간 누적 컨텍스트의 구체적 내용을 근거로 한다 (범용적 조언 X).
  작성 원칙은 4단계 「원점 사고 원칙」을 따른다
- **「의사 결정 조언」**은 향후 1주일 내 실제 실행 가능한 것만 넣는다. **포트 인지 구간**이므로
  1-3단계 스냅샷의 보유 수량·평단·비중을 근거 수치로 쓰고, 손절/익절은 실제 가격으로 환산한다.
  1-3-1단계에서 전고점 낙폭이 발동한 종목은 **고점 기준 낙폭과 평단 기준 수익률을 함께 인용**해
  손절 문제인지 추세 훼손 문제인지 구분한다. 고점 낙폭을 인용할 때는 **52주 시장 축인지 계좌
  기록 축인지를 반드시 명시**하고, 두 축이 갈리면 낙폭이 매수 이전에 생긴 것인지 보유 구간에
  생긴 것인지를 그 차이로 설명한다. 포트폴리오 표를 통째로 옮기지 않는다

## 주의사항

- 링크 내용을 읽을 수 없었던 경우에도 메시지 제목/맥락으로 최대한 판단한다
- 이미지를 읽을 수 없었던 경우에도 캡션/맥락으로 최대한 판단한다. 이미지에서 읽은
  수치는 원문 텍스트와 같은 기준으로 다루되 출처를 밝힌다
- 수치(목표주가, 실적 등)는 원문에 명시된 것만 사용한다 — 추측 금지
