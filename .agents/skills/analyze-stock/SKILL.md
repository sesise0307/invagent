# 종목 분석 스킬 (Analyze Stock)

종목명 → 로컬 리포트 + DART 사업보고서 델타 + 웹 최신정보 + 내 아카이브 이력 + 포트폴리오 비교 → 투자 판단 → `output/reports/종목/<초성>/<종목명>_<yyyy-mm-dd>.md` 저장.

추정이 아니라 **원문 기반**이 핵심 가치다. 리포트 PDF·DART 공시·실제 포트폴리오 스냅샷을 읽고 쓴다.

---

## 기본 동작 모드

`caveman` 스킬을 `full` 강도로 활성화한다. 대화 응답과 **보고서 본문**에 같은 강도를 적용한다.
Codex는 `$caveman:caveman full`, Claude Code는 `/caveman:caveman full`.

## 실행 순서

각 단계는 **비블로킹**이다. 실패하면 보고서 해당 섹션에 `미수집 — <사유>` 한 줄만 남기고
나머지 단계를 정상 진행한다. 한 단계 실패가 보고서 생성을 막아서는 안 된다.

### 1단계 — 요청 해석

- 종목명 + 추가 요청(예: "밸류에이션만", "경쟁사까지", "리포트 10개 다 봐")을 분리한다.
- 종목명이 모호하면(동명 이종목, 지주사/사업회사 혼동) **먼저 물어라.**
- 추가 요청이 특정 섹션만 가리키면 나머지 단계는 축약하되 **8단계 포트폴리오 비교, 9단계 목표주가 산정,
  10단계 판단은 생략 금지.**

### 2단계 — 과거 보고서 승계

같은 종목 보고서가 이미 있으면 **백지에서 다시 쓰지 않는다. 승계해서 최신화한다.**

```bash
uv run python .agents/skills/analyze-stock/scripts/find_prior_report.py "<종목명>"
```

- **`output/reports/종목/<초성>/<종목명>_<yyyy-mm-dd>.md`만 승계 대상**이다.
  `산업/`·`기타/`의 비교·섹터·전략 보고서는 다른 종목 내용도 담겨 있으므로
  **참고로만 읽고 원본을 유지한다.**
- 승계 대상이 있으면 **전문을 읽는다.** 읽고 다음을 쥔 채 이후 단계로 간다:
  - **`개정 이력` 절 전체 — 반드시 읽는다 (현 템플릿 `## 11.`, 옛 배치 `## 12.`).** 본문은 현재 상태로 덮이므로 **과거의 나는 여기에만 남는다.**
    과거 판단이 언제 왜 뒤집혔나 · 이미 정정한 항목(같은 실수 반복 금지) · ⚠️/⛔ 경고.
    안 읽으면 과거에 회피 판정한 종목을 근거 없이 다시 산다.
    10단계 현재 판단과 §1 「과거 내 판정 대비」는 이 절을 입력으로 쓴다.
  - 이미 확인된 사실 — 다시 조회하지 않는다
  - 당시 판단 · 목표가 · 진입 조건
  - **검증 대기 항목** — 「이걸 확인하면 판단이 바뀐다」고 써 둔 것
  - 수치·기준(연결/별도, 기간)이 의심스러운 곳 → 이번에 원본으로 재확인할 목록
- **이력 압축 조건**:
  - **본문 11섹션은 현재 상태만 담는다.** 옛 본문을 절에 남기지 않는다.
    `### YYYY-MM-DD 업데이트` 블록과 `### {날짜} 기존 분석 (보존)` 블록은 폐지됐다. 새로 만들지 마라.
  - 사실·판단이 바뀌면 해당 절을 **최신값으로 덮고**, `## 11. 개정 이력`에 한 줄 남긴다.
  - 형식은 `- {yyyy-mm-dd}: {구분} — {요약}` 한 줄. 구분은 **정정 / 갱신 / 판단변경**.
    **정정·판단변경은 근거(rcept_no · 리포트 파일명 · URL + 기준일)를 줄 안에 붙인다.** 갱신은 선택.
    이력 줄은 지우지 않고 무제한 누적한다.
  - **승계본이 옛 형식(날짜 블록·보존 블록 누적)이면 이번 실행에서 §11로 이관한다.**
    각 블록을 그 날짜의 한 줄로 접어 §11에 **먼저 올린 뒤** 본문에서 뺀다.
    순서를 지켜라 — 본문만 지우고 §11에 안 올리면 이력이 사라진다. 사용자 승인은 필요 없다.
  - 접어도 **잃으면 안 되는 것**: 승계본 고유 분석의 결론, ⚠️/⛔ 경고, 검증 대기 항목, 과거 판단과 근거.
    전부 §11 한 줄 또는 §9·§6의 현재 항목으로 살린다. 요약은 사실·수치·근거를 남기고 서술만 죽인다.
  - 종목별 보고서는 **누적 파일 1개만 유지**한다. 승계본 날짜가 오늘과 다르면 내용을 복사하지 말고 파일명을 오늘 목표 경로로 먼저 변경한 뒤 그 파일을 편집한다.
  - 이름 변경 전 원본 경로와 목표 경로를 정확히 확인한다. 목표가 이미 존재하면 덮어쓰지 말고 두 파일의 고유 내용을 먼저 병합한다.
- **증분 기준일** = 승계본의 작성일. 이후 단계는 이 날짜 이후만 새로 수집한다:
  - 4단계 리포트: `find_reports.py "<종목명>" --since <기준일>`
  - 5단계 DART: 기준일 이후 신규 공시 위주. **사업보고서 델타는 기준일과 무관하게 항상 수행**
  - 6단계 시세·컨센서스·리포트 요약: `fetch_stock_info.py "<종목명>" --since <기준일>`
  - 7단계 아카이브: `find_mentions.py "<종목명>" --since <기준일>`
- 승계 대상이 없으면 신규 작성. 이후 단계는 `--since` 없이 전체 수집한다.
- 승계 조회가 실패하면 수집은 계속하되, 저장 전 승계 대상을 다시 확인한다. 조회 실패를
  「기존 보고서 없음」으로 간주하지 않는다. 확인할 수 없으면 원본을 건드리지 않고 초안만 남긴다.

**오류 정정** (승계 시 전 단계에 걸쳐 적용)

- 승계본의 수치·논리가 이번에 확인한 원본과 어긋나면 **본문은 정정값으로 덮고 §11에 `정정` 한 줄을 남긴다.** 조용히 덮지 마라 — 덮은 사실이 §11에 없으면 정정이 아니라 은폐다.
- 정정 대상: 틀린 수치, 기준 혼동(연결↔별도, 분기↔TTM), 이후 사건으로 무효가 된 전제,
  근거 없이 쓴 추정.
- **정정에는 근거를 붙인다** — rcept_no · 리포트 파일명 · URL + 기준일.
- 승계본에만 있는 고유 분석은 **결론과 근거를 현재 절에 살린다.** 여전히 유효하면 본문에 그대로 두고,
  무효가 됐으면 §11에 `판단변경` 한 줄로 접는다. 근거 없이 통째로 버리지 않는다.
- 승계본이 옛 형식(서술형)이면 **템플릿 11섹션 구조로 재구성**한다. 과거 서술은 §11 한 줄로 접고
  본문에는 현재 상태만 남긴다. 사실·수치·근거를 잃지 않는 게 우선이다.
- 승계본이 옛 12섹션 배치(`## 2. 사업 구조`로 시작해 `## 12. 개정 이력`으로 끝남)면 **템플릿 순서로
  재배치**한다. 옛 §3 리포트 컨센서스는 §2-A로, 옛 §5-A·B·C는 §2-B·C·D로 들어가고 나머지 절은
  이름대로 옮긴다. 재배치는 자리만 바꾼다 — 내용은 그대로 옮기고 갱신은 평소대로 한다.

### 3단계 — 사용자 룰 로드

- 저장소 루트 기준 `context/my_rules.md`를 **반드시 읽는다.**
- 4개 절(기본 원칙 / 매매 규칙 / 레버리지 사용 규칙 / 기술적 분석 규칙)이 각각 1번부터 다시 시작한다.
  인용할 때 **절 이름 + 번호 + 원문**을 그대로 쓴다. 예: 「매매규칙 6. -15%, -20% 손절」.
- 파일 내 「적용 방법」 절의 지침(손절선 가격 환산, 2%룰 포지션 크기, 위반 시 서두 경고)을 따른다.

### 4단계 — 로컬 리포트 수집·독해

아카이브는 `~/1_Investment/리포트/<초성>/<종목명>/`. 직접 `ls`로 뒤지지 말고 스크립트를 쓴다.

```bash
uv run python .agents/skills/analyze-stock/scripts/find_reports.py "<종목명>" --limit 5
```

- 기본 최근 5개. 사용자가 개수를 지정하면 `--limit N`, 전부면 `--all`, 기간이면 `--since YYYY-MM-DD`.
- 스크립트가 초성 폴더 라우팅·`IR자료/` 하위·`_0_To_Read`·`_산업분석` 보조 검색·최신순 정렬을 처리한다.
- ⛔ 매칭이 `exact`가 아니고 후보가 여러 개면 **어느 종목인지 사용자에게 확인한다.**
  애매한 채로 진행하지 마라. 엉뚱한 종목 리포트를 읽는 것이 아무 리포트도 안 읽는 것보다 나쁘다.
- 반환된 PDF를 파일 읽기 기능으로 읽는다. PDF는 10쪽 초과 시 페이지 범위 지정이 필요하다.
  기본 `1-10`쪽을 읽고, 목차상 더 필요하면 범위를 늘린다.
- 리포트마다 뽑을 것: **발간일 · 증권사 · 투자의견 · 목표주가 · 핵심 논리 1줄 · 논리의 전제.**
- **시각 변화 추적이 이 단계의 핵심.** 오래된 리포트 → 최신 리포트로 목표가·논리가 어떻게 움직였나,
  과거 전제 중 무엇이 틀렸나, 지금도 유효한 전제는 무엇인가.
- 리포트는 **매도 의견을 거의 안 낸다.** 목표가를 그대로 믿지 말고 전제를 검증 대상으로 다뤄라.
- 보고서 §2-A 목표주가 표는 **StockEasy 기준(6단계)이다.** 로컬 PDF는 표에 넣지 않는다.
  여기서 뽑은 목표가·의견은 StockEasy 값과 대조해 어긋나면 표시하고, 본문에는 **논리·전제**를 쓴다.

### 5단계 — DART 사업보고서 델타 (`opendart` 스킬 위임)

도구 사용법은 `../opendart/SKILL.md` 참조. MCP 서버가 없으면 웹검색으로 대체하지 말고 미수집 처리한다.

1. `company` — ticker·corp_code 확정. 이후 도구에 그대로 넘겨 재식별을 막는다.
2. `business_details` — **최신 사업보고서 + 직전 사업보고서 2건.** 이 스킬의 차별점.
   사업 내용·제품별 매출 구성·생산능력/가동률·주요 계약·연구개발·원재료 조달을 대조해
   **신설 / 삭제 / 수치 이동** 3분류로 정리한다.
   - 신설: 새 사업부·새 제품·새 고객·새 설비·새 리스크 문구
   - 삭제: 사라진 사업·중단된 라인·빠진 고객
   - 수치 이동: 매출 구성비·가동률·CAPEX·R&D 비율·원재료 단가가 어디로 움직였나
3. `financial_metrics` — `scope=yearly`(`years=3`) + `scope=quarterly`(최신 반기·분기 보완).
4. 해당 시 보조 호출: `valuation`, `order_contracts`.
   `dilutive_issuance` · `treasury_share` · `ownership_structure` · `risk_events`는 5-1단계에서 호출한다.
5. **Evidence/rcept_no 인용 필수.** 도구가 주지 않은 값은 「공시에서 확인 안 됨」으로 적는다.
   추정으로 메우지 말 것. 기준(연결/별도, 확정/잠정)은 숫자에 붙여 다닌다.

### 5-1단계 — 오버행 · 수급 점검 (참고)

**참고 사항이다.** 물량과 일정을 알고 들어가도록 보여 주는 정보이고, 10단계 최종 판단·확신도·
진입 경로·1차 수량은 이 결과와 무관하게 낸다. 출력은 `template/stock_analysis.md` §4-A.

| 물량 | 도구 · 출처 | 뽑을 것 |
|---|---|---|
| CB · BW · 전환우선주 | `dilutive_issuance` | 잔여 전환가능 주식수 · 전환청구 개시일 · **리픽싱 예정일과 조정 방향** |
| 유상증자 · 제3자배정 | `dilutive_issuance` | 발행 주식수 · 납입일 · 신주 상장일 |
| 보호예수 · 임원 락업 | 상장 공시 · 웹 · 6단계 뉴스 | 해제 주식수 · **해제일** |
| 대량보유 변동 · 블록딜 | `ownership_structure` + 6단계 뉴스 | 매도 주체(FI/전략투자자/관계사) · 주식수 · 공시일 |
| 자사주 | `treasury_share` | 취득/소각 구분 · 규모 · 기간 |
| 내부자 | `ownership_structure` + 뉴스 | 장내매수 vs **스톡옵션 행사** 구분 · 주체 · 금액 |
| 조달 리스크 | `dilutive_issuance` · `risk_events` · 뉴스 | 발표된 CAPEX·투자 대비 **조달 방식 확정 여부** |

- **규모는 반드시 상장주식수 대비 %로 환산한다.** 절대 주식수만 적으면 크기를 알 수 없다.
- **일정이 있는 물량은 날짜를 §4 「예정 촉매」에도 같이 올린다.** 해제일·개시일·리픽싱일은 촉매다.
- **조달 방식 미확정은 「없음」이 아니라 「미확정」이다.** 대규모 CAPEX·시설투자 공시가 있는데
  재원이 「내부 유보 또는 외부조달」 수준으로만 밝혀져 있으면 → **회사채면 중립, 메자닌(CB·BW)이면 희석.**
  확정 전에는 오버행 항목을 미해소로 둔다.
- ⚠️ **스톡옵션 행사는 내부자 장내매수와 다르다.** 행사가가 현재가보다 낮아 행사한 것은
  「싸다는 판단」이 아니라 「행사이익이 난다는 계산」이다. 강세 신호로 승격하지 마라.
- ⚠️ **FI(재무적 투자자)의 전량 처분은 오버행 해소이자 동시에 매도 압력**이다. 양쪽을 다 적는다.
- 항목이 없으면 `해당 없음`, MCP·조회가 막혔으면 `미수집 — [사유]`. **빈칸 금지.**
- 산출물 마지막 줄은 **요약 한 줄** — `오버행 해소 / 미해소 / 해당 없음` + 주목할 일정.
  10단계는 이 줄을 §5에 참고로 인용만 한다.

### 6단계 — 시세 · 컨센서스 (StockEasy)

시세·멀티플·52주·증권사별 목표주가·컨센 추정 실적·EPS 컨센 변화·뉴스는 **StockEasy가 단일 출처다.**
다른 사이트 숫자를 섞지 않는다.

```bash
uv run python .agents/skills/analyze-stock/scripts/fetch_stock_info.py "<종목명 또는 6자리 티커>" \
  [--since <기준일>] [--news 10] [--reports 12] [--summaries 5] [--disclosures 10] [--detail-chars 800] [--no-cache]
```

- 티커는 **5단계 `company`가 확정한 값을 그대로 넘긴다.** 재식별을 막는다. 5단계가 실패했으면 종목명을 넘긴다.
- 종료 코드: `1` 수집 실패 → `미수집 — StockEasy 조회 실패` 한 줄. `2` 종목명 후보 다수 →
  **stderr의 후보를 사용자에게 보여주고 되묻는다** (1단계 「종목명 모호하면 먼저 물어라」와 동일).
- 승계 작성이면 `--since <기준일>`. 뉴스는 기준일 이후만 나오고, 기준일 이후 신규 리포트에 `🆕`가 붙는다.
- 출력 해석 시 주의:
  - `[52주 밴드 내 위치]`는 10단계 추세 관점의 진입 조건 근거로 쓴다.
  - `[시간외·NXT]`는 KRX 시간외·NXT 체결가를 **정규장가 대비**로 보여 주는 참고줄이다. 손절·발동가·
    이평 거리·상승여력은 전부 `[시세]`(정규장 종가)로만 잰다 — 시간외가를 판정 가격으로 옮기지 않는다.
    다음 날 갭 방향을 가늠하는 맥락으로만 쓴다.
  - `[공시]`는 StockEasy 소식 탭의 DART 공시 **목록**(최근 20건 창, `--since`면 기준일 이후)이다.
    5단계 사업보고서 델타와 5-1단계 오버행 점검에서 **빠진 접수번호가 없는지 대조하는 체크리스트**로만
    쓰고, 본문 판독은 `opendart` 스킬로 한다. 목록에 있는 제목만 보고 내용을 추정해 쓰지 않는다.
  - 분기 표에 같은 분기가 `확정`+`추정 E` 두 줄로 나오면 **컨센 대비 서프라이즈/쇼크**다. 반드시 대조한다.
  - ⛔ `추정 E` 행은 **증권사 컨센서스이지 공시가 아니다.** DART 확정치와 같은 표·같은 행에
    나란히 놓지 않는다. 대조할 때는 「확정 vs 컨센」임을 명시한다.
- 출처 표기: `StockEasy stock-info/<티커>` + 조회일. 스크립트 첫 줄에 URL과 조회일이 찍힌다.
- 응답은 짧은 TTL로 캐시된다. 같은 실행에서 이어 도는 `stage_scan.py`가 `info-tab`을 다시 받지
  않게 하려는 것이다. 캐시 오염이 의심되면 `--no-cache`. 규칙은 `market-data` 스킬 참조.

**스테이지 판정 (`stage-analysis` 스킬 스크립트)**

시세를 받은 뒤 같은 티커로 단계 판정을 함께 돌린다. 방법론은 `../stage-analysis/SKILL.md`.

```bash
uv run python .agents/skills/stage-analysis/scripts/stage_scan.py "<5단계가 확정한 티커>"
```

- 일봉은 StockEasy `info-tab` 정규장 일봉(쿠키 필요, 없거나 실패하면 네이버 `siseJson`으로 대체하고 출력에 꼬리표), 영업이익 증가율은 StockEasy `info-tab`이다. 네이버 대체 꼬리표가 붙으면 가격선 거리를 6단계 StockEasy 종가로 다시 잰다. 쿠키가 없으면
  **가격 전용 판정으로 강등**되고 그 꼬리표가 출력에 붙는다 — 꼬리표째 §5로 옮긴다.
- 출력의 `판정`·`직전 순환적 고점/저점` 줄은 10단계 📈 추세 관점과 §5 첫 불릿의 입력이다.
- 실패하면(exit 1, 일봉 부족·조회 실패) §5 스테이지 줄에 `미수집 — …`만 남기고 진행한다.
  **모델이 눈대중으로 단계를 매기지 않는다.**

**단기 바닥 전환 판정 (`stage-analysis` 스킬 스크립트)**

스테이지 다음에 같은 티커로 돌린다. 「매매규칙 2」의 '바닥 다진 후 고개 드는 초반'의 정본이고,
1·3·4단계 종목의 진입 타이밍 게이트다. 방법론은 `../stage-analysis/SKILL.md` 「단기 바닥 전환 판정」.

```bash
uv run python .agents/skills/stage-analysis/scripts/turn_scan.py "<5단계가 확정한 티커>"
```

- 일봉만 쓴다 — StockEasy `info-tab` 정규장 일봉(쿠키 필요, 없거나 실패하면 네이버 `siseJson`으로 대체하고 출력에 꼬리표). 쿠키가 없어도 판정은 돈다.
- 출력의 `판정`·`감시선` 줄은 §5 📈 「단기 바닥 전환」 불릿과 10단계 진입 경로·증량 트리거의 입력이다.
  상태 코드를 `entry_policy.py`의 `turn`으로 넘긴다 — 하락 중 `falling` / 바닥 다지기 `basing` /
  고개 들기 `turning` / 초입 지남 `extended`.
- `바닥 다지기`면 출력의 `선매집(경로 C) 가격 조건` 줄도 읽는다. `--json`의 `accumulation.eligible`과
  위 `stage_scan` 출력의 `전년 동기 대비 증가`(= `op_growth.latest.increased`)를 `entry_policy.py`의
  `accumulation`으로 넘긴다 — `{"status":"ok","eligible":…,"op_yoy_increased":…}`. 실적이 `모름`이면
  `op_yoy_increased`는 `null`이다.
- 실패하면(exit 1) §5에 `미수집 — …`만 남긴다. 경로 B·C는 `미수집`이면 열리지 않는다.
  **모델이 차트를 눈대중해 상태를 매기지 않는다.**

**CAN SLIM 점검 (참고 — 판단 미반영)**

같은 티커로 오닐 CAN SLIM 7항목을 결정론적으로 채점한다. **참고 지표다.** 10단계 최종 판단·확신도·
진입 경로·1차 수량·`entry_policy.py` 입력 어디에도 넣지 않고, §5 「📋 CAN SLIM 점검」에 그대로 옮겨
지켜본다(사용자 결정, 2026-10-05). 방법론 배경은 `../advice/references/trend_following.md`.

```bash
uv run python .agents/skills/analyze-stock/scripts/canslim_scan.py "<5단계가 확정한 티커>" [--json] [--no-cache]
```

| 항목 | 상수 | 값 | 기준 · 출처 |
|---|---|---|---|
| C 분기 EPS | `C_MIN_EPS_YOY_PCT` | 25 | 최근 확정 분기 EPS 전년 동기 대비 +25% 이상. 흑자전환은 충족, 적자는 미충족. `info-tab` 분기 재무 |
| A 연간 EPS | `A_YEARS` | 3 | 확정 연간 EPS가 3년 연속 증가하고 최근 연도가 흑자. 3년 CAGR을 함께 적는다. `info-tab` 연간 재무 |
| N 신고가권 기간 | `N_HIGH_WINDOW` | 250 | 52주 = 250거래일 **종가** 고점. 장중 고가는 쓰지 않는다 |
| N 신고가권 거리 | `N_MAX_BELOW_HIGH_PCT` | 15 | 종가가 그 고점 대비 -15% 이내. 오닐 「신고가 근처에서 산다」를 가치주 변동성에 맞춰 잡은 값 |
| S 창 | `S_WINDOW` | 50 | 최근 50거래일 |
| S 매집 비율 | `S_MIN_UPDOWN_RATIO` | 1.0 | 상승일 거래량 ÷ 하락일 거래량이 1.0 초과면 매집 우위. 상장주식수·유통비율은 참고로 적는다 |
| L 상대강도 | `L_MIN_RS` | 80 | StockEasy `info-tab`의 `rs_data.rs` 80 이상. 1M·3M·6M과 RS선 신고가 여부를 함께 적는다 |
| I 기관 창 | `I_WINDOW` | 20 | 네이버 투자자별 매매동향, 최근 20거래일 **기관** 누적 순매수 > 0. 60일 누적·외국인은 참고 |

M은 상수가 아니라 StockEasy 빅픽처의 종목 상장 시장 상태다 — `상승 추세 확인` ✅, `상승 추세 압박`
⚠️ 경계(점수 미산입), `랠리 시도`·`조정장` ❌.

- 점수는 ✅ 개수만 센다: `점수 N/7 · 경계 … · 미수집 …`. ⚠️·❓는 ❌와 섞지 않고 따로 적는다.
- N은 **스크립트 가격 조건 + §4 촉매가 둘 다 있어야** ✅다. 스크립트가 ✅여도 신제품·신사업·경영진
  교체·실적 서프라이즈 같은 변화가 §4에 없으면 ❌로 내리고 그 사유를 적는다. 스크립트가 ❌면 촉매가
  있어도 ❌다. 나머지 6항목은 스크립트 값을 그대로 옮긴다 — 모델이 다시 매기지 않는다.
- 우선주: C·A는 본주 실적, N·S·L·I는 우선주 자기 시세다. StockEasy가 우선주 RS를 주지 않으면
  L은 ❓이고 본주 RS가 참고로 붙는다. 본주 RS로 채점하지 않는다.
- 쿠키가 없거나 `info-tab`이 실패하면 C·A·N·S·L이 ❓로 남고 I만 채점된다(exit 0, stderr `[누락]`).
  상장 시장은 그때 네이버(`naver.fetch_listing_market`)에서 받아 M을 채점하고, 출처 줄에 그 사실이
  붙는다. 네이버까지 실패하면 M도 ❓다 — KOSPI로 가정하지 않는다.
- 업종 RS(`/rs/dashboard-data`)는 앱 토큰을 요구해 HTTP 403이다 — 받지 않는다(`market-data` 원칙 3).

**웹 검색은 스크립트가 안 주는 것만 보강한다:**

- 업황 · 전방 수요 · 원자재/환율 등 마진 드라이버
- 경쟁사 동향 (같은 밸류에이션 축으로 비교 가능한 곳)
- 스크립트 뉴스 목록에서 **판단에 걸리는 건만** 골라 원문 조회

수치마다 출처 URL과 기준일을 붙인다. 출처 없는 숫자는 쓰지 않는다.

**리포트 요약 (`[리포트 요약]` 섹션)**

같은 스크립트가 `securities-reports` API에서 최신 리포트의 요약 논지까지 받아온다.
스크립트는 `.env`의 `STOCKEASY_COOKIE`(브라우저에서 복사한 Cookie 헤더 전문)를 읽어 붙인다.

⛔ **`stock-search`를 뺀 전 엔드포인트가 로그인 세션을 요구한다.** 쿠키가 없으면 시세·멀티플·
컨센까지 통째로 못 받고 스크립트가 exit 1로 쿠키를 사유로 지목한다. **6단계 전체가 막히므로
이때는 사용자에게 쿠키 갱신을 먼저 요청한다.** 갱신 절차와 401 증상 구분은 `market-data` 스킬이
정본이다 — 여기서 다시 적지 않는다.

- 리포트마다 나오는 것: **발간일 · 증권사 · 애널리스트 · 투자의견/목표가 · 제목 · 요약 논지 불릿.**
  기본 5건(`--summaries N`), 본문까지 보려면 `--detail-chars 800`.
- `--since`를 주면 `date_from`으로 넘어가 기준일 이후 발간분만 받는다.
- 쿠키가 유효한데 이 API만 실패하면 이 섹션만 `미수집 — …`으로 비고 나머지는 정상 출력된다(비블로킹).
  - `STOCKEASY_COOKIE 미설정` → 사용자에게 `.env`에 넣어 달라고 **한 번만** 알린다.
  - `HTTP 401 (쿠키 만료·무효)` → 사용자에게 쿠키 갱신을 알린다.
  - ⛔ 쿠키 값을 대화·보고서·로그에 출력하지 않는다. 스크립트도 값을 찍지 않는다.
  - ⛔ 401을 브라우저 직접 호출로 우회했다면, **쿠키 복구 후 반드시 스크립트로 재검증한다.**
    수동 집계는 증권사별 최신 dedupe에서 누락이 난다(2026-08-18 조선 3사에서 3사·5사 누락 실측).
- 각 리포트의 `파일:` 줄은 로컬 아카이브와 **같은 파일명 규칙**이다. 4단계에서 읽은 PDF와 겹치는지
  이걸로 판정한다. 겹치면 **PDF 원문 쪽을 우선**하고, 겹치지 않는 건만 요약에서 보충한다.
- ⛔ 요약 본문도 리포트 PDF 원문도 보고서에 통째로 옮기지 않는다. 논지·수치·전제만 추출한다.

### 7단계 — 내 아카이브 이력

이미 내가 이 종목에 대해 써 둔 것을 찾는다. 대상은 `output/daily-digest/`의
누적 인덱스 `monthly_context.md` · 테마 파일 `themes/` · 일일 브리핑 `<YYYY-MM>/<YYYY-MM-DD>.md`.

```bash
uv run python .agents/skills/analyze-stock/scripts/find_mentions.py "<종목명>" --count-only
uv run python .agents/skills/analyze-stock/scripts/find_mentions.py "<종목명>" --alias "<축약형>" --top 20
```

- 스크립트는 **위치만 알려준다. 본문은 원본을 직접 읽어라.** 출력의 `경로:줄번호`를 쓴다.
  1. `monthly_context.md`는 **항상 전체를 읽는다** (`daily-digest` 읽기 프로토콜).
  2. 로케이터가 가리키는 테마 파일 중 **이 종목과 직접 겹치는 것만** 연다. 전부 열면 컨텍스트가 마른다.
  3. 일일 브리핑은 `head` 매치 건부터 연다. `body` 매치는 스치듯 언급이라 건수만 참고한다.
  4. ⛔ 로케이터 발췌만 보고 결론 쓰지 말 것. 잘린 텍스트다.
     결론을 좌우하는 근거는 반드시 해당 경로의 원본 줄을 열어 확인한다.
- 아카이브는 축약형을 쓴다(삼전, HD현중, 하나머티, 전닉, LG지주). **아는 축약형은 `--alias`로 넘긴다.**
  안 넘기면 놓친다. 히트가 많으면 `--count-only`로 먼저 재고 `--top`을 조절한다.
- 뽑을 것 — **과거의 나와 지금의 나를 대조하는 것이 이 단계의 목적이다**:

  - 당시 논지 → 지금 검증 (맞음 / 틀림 / 미확정)
  - `⭐`(확신) `⚠️`(경고) `⛔`(회피 판정) 마커 항목은 전부 승계한다.
    **과거에 회피 판정한 종목을 근거 없이 다시 사지 않는다.**
  - 인덱스 「주요 이벤트 캘린더」에 이 종목 예정 이벤트가 있으면 6단계 촉매와 합친다
  - 종료된 논쟁 vs 아직 열린 논쟁
- 히트 0이면 `미수집 — 아카이브 언급 없음` 한 줄. 신규 발굴 종목은 0이 정상이다.

### 9단계 — 목표주가 산정

수치 입력은 `scripts/validate_inputs.py`의 상태·시점·관점 봉투를 먼저 통과시킨다. 합의·시나리오 범위와 위험 한도 계산은 `scripts/valuation_decision.py`로 재현하고 JSON의 `audit`를 근거로 보존한다.

**컨센 목표가 단독으로 판정하지 않는다.** 증권사 리포트는 매도 의견을 거의 안 내 목표가가 구조적
상방 편향이다. 컨센과 **자체 Bull/Base/Bear 시나리오**를 동적 가중으로 결합한다.
출력 형식의 정본은 `template/stock_analysis.md` §2-C·§2-D.

⛔ **목표주가·기대수익을 숫자 하나로 내지 않는다. 반드시 범위로 낸다.**
컨센 평균은 중심 추정치로는 쓸모 있지만 **분산도를 전혀 전달하지 못한다.** 12사가 8만~9만원에
몰린 경우와 5만~15만원으로 갈린 경우가 같은 평균 10만원으로 붕괴한다. 시나리오 3점과
컨센 최고/최저를 **각각** 결합해 분산을 살린다.

**입력**

| 출처 | 쓰는 것 |
|---|---|
| 6단계 StockEasy | 평균 목표가 · 커버 사수 · 최신 리포트 발간일 · 목표가 산포(최고/최저) · 상향/하향 · EPS 컨센 변화 · 연간 컨센 추정 실적 |

> ⛔ **컨센 입력은 스크립트 `[컨센 요약]` 줄을 그대로 쓴다.** 이 줄은 **증권사별 최신 1건**만
> 집계한 값이다. 바로 아래 `↳` 줄의 「전체 이력 단순평균」은 옛 목표가·중복이 섞여 있어
> **blend 입력이 아니다.** 목표주가 표를 손으로 훑어 평균·최저를 직접 세지 마라 —
> 최신분이 오래된 증권사가 표 밖에 있어 커버 수와 최저값이 어긋난다.
| 5단계 DART | 확정 실적 · CAPEX · 가동률 · 매출 구성 · 수주 |
| 4단계 리포트 | 목표가의 **전제** (논리·가정) |
| 6단계 웹 | 업황 · 전방 수요 · 원자재/환율 등 마진 드라이버 |

**시나리오 3종 (§2-C)**

- 각 시나리오는 **드라이버 가정 → 실적 → 적용 멀티플 → 목표가** 순으로 세운다.
  「좋아지면/나빠지면」 식 서술 금지. **수치 가정 필수.**
- 적용 멀티플 축은 PER / EV-EBITDA / PBR / SOTP 중 **택 1 + 사유.** 적자·사이클 바닥이면 PER 금지.
- 멀티플 근거는 §2-B 과거 밴드·섹터 평균에서 끌어온다. **근거 없는 멀티플 금지.**
  Bull = 밴드 상단/리레이팅, Base = 밴드 중단/섹터 평균, Bear = 밴드 하단/디레이팅.
- **컨센 추정 실적을 그대로 베끼지 않는다.** 출발점으로 쓰되 어디를 왜 올렸는지/내렸는지 한 줄씩 남긴다.
- 확률 합 = 100%. 확률가중가 = Σ(확률 × 목표가)를 명시한다.

**가중치 `w_c` 결정**

위에서부터 **처음 걸리는 것 하나만** 적용한다. 중복 감산 없다.

```
1. 컨센 산포(최고/최저) > 2배            → w_c = 0.3
2. 커버 ≤2사 or 최신 리포트 > 6개월       → w_c = 0.3
3. 커버 ≥8사 & 최근 3개월 리포트 ≥3건     → w_c = 0.65
4. 그 외                                → w_c = 0.5

마지막에 EPS 컨센 하향 지속이면 -0.1 (하한 0.2)
w_s = 1 - w_c
```

- **순서가 곧 충돌 해소다.** 산포·stale·얇은 커버는 전부 「컨센이 한 값으로 수렴하지 않는다」는
  신호이므로 1·2를 3보다 위에 둔다. 커버 증권사가 아무리 많아도 값이 갈리면 평균의 정보량은 낮다.
  **커버 수는 산포를 못 이긴다.**
- 조정 사유를 §2-D 「가중치」 칸에 **한 줄로 남긴다.** 몇 번 규칙이 걸렸나.

**3점 결합 (§2-D)**

컨센과 시나리오를 **3점 각각** 같은 가중치로 결합한다.

```
하단 = w_c × 컨센최저목표가 + w_s × Bear목표가
중심 = w_c × 컨센평균목표가 + w_s × 시나리오확률가중가
상단 = w_c × 컨센최고목표가 + w_s × Bull목표가

기대수익(하단/중심/상단) = (각 목표가 - 현재가) / 현재가
```

- **중심은 「중간값」이 아니라 확률가중 기댓값이다.** Base 목표가와 달라도 정상이다.
  Base와 크게 갈리면 확률 배분이 비대칭이라는 뜻 — §2-C에 한 줄 남긴다.
- 순서는 자동 보장된다(볼록결합). `하단 ≤ 중심 ≤ 상단`이 깨지면 **입력이 틀린 것이다.** 다시 봐라.

**분산도 지표 (필수 출력)**

평균이 못 주는 것을 명시적으로 뽑는다.

```
범위 폭      = (상단 - 하단) / 중심
컨센 산포    = 컨센최고 / 컨센최저          (배수)
시나리오 산포 = Bull목표가 / Bear목표가      (배수)
```

- 범위 폭이 크면 「모른다」는 뜻이다. 그대로 확신도 산출에 들어간다.
- 컨센 산포와 시나리오 산포를 **나란히 적고 어느 쪽이 넓은지 한 줄로 해석한다.**
  컨센 좁고 내 시나리오 넓음 → 시장이 합의한 것을 내가 의심한다. 반대면 그 반대.

**blend 금지 조건**

```
컨센 범위 [컨센최저, 컨센최고] 와 시나리오 범위 [Bear, Bull] 이 전혀 겹치지 않으면 → blend 금지
```

겹치지 않는다 = 두 추정이 양립 불가능하다. 평균 내지 말고 괴리 원인 + 채택할 쪽 + 사유를 쓰고
**그 쪽 범위를 그대로 종합 범위로 쓴다.** 부분 겹침이면 정상 blend 한다.

**판정선 (사용자 룰 기준)**

**중심 + 하단** 두 축으로 판정한다. 하단은 가정에 따른 시나리오 하방이며 실측 손실 한도가 아니다.

```
하방        = (현재가 - 하단목표가) / 현재가      ← 음수면 「하방 막힘」
실효 손절폭  = max(하방, 20%)                     ← 「매매규칙 6」 최종 이탈선이 하한. 2%룰 분모
손익비 분모  = max(하방, 15%)                     ← 손익비 전용. 실효 손절폭과 다른 값이다
손익비      = 중심 기대수익 / 손익비 분모

판정 (위에서부터 처음 걸리는 것):
1. 중심 ≥50%                  → 🟢 매수 후보  (「기본 원칙 2」 본문 50~100% 충족)
2. 중심 30~50% & 하방 ≤ 0%    → 🟢 매수 후보  (「기본 원칙 2」 단서 — 하방 막힘. 근거 1줄 필수)
3. 중심 ≥25%                  → 🟡 관망 — 촉매/조정 대기
4. 그 외                      → 🔴 회피

강등 (각각 한 단계씩, 매수→관망→회피):
손익비 < 2.0
하단 기대수익 < -30%           ← 기존 하방 꼬리 강등 기준; 20% 손절폭 하한의 1.5배
```

- 2번 「하방 막힘」은 **하단목표가 ≥ 현재가**로 기계 판정한다. 근거 1줄을 강제한다 —
  순현금 / 자산가치 / Bear 가정의 보수성 중 무엇이 받치는가.
- ⛔ **두 분모는 다른 것을 잰다. 하나로 합치지 마라** (사용자 확정 2026-09-22).

  | 값 | 하한 | 쓰이는 곳 | 하한의 근거 |
  |---|---|---|---|
  | 실효 손절폭 | 20% | 2%룰 매수원금 상한 · 진입 시 손절가 환산 | 「매매규칙 6」은 -15% 1차 분할, **-20% 전량**. 포지션이 실제로 낼 수 있는 최대 손실이 -20%이므로 2%룰 분모는 20%다. 15%를 쓰면 1회 최대 손실이 계좌의 2.67%가 되어 「기본 원칙 4」를 넘긴다 |
  | 손익비 분모 | 15% | 손익비 산출 하나뿐 | 손익비는 **시나리오 하방 대비 보상**을 재는 값이다. 20%에 묶으면 하방이 막힌 종목도 분모 20%를 받아 손익비가 `중심 기대수익 ÷ 20%`로 붕괴하고, 「중심 ≥50%」와 같은 축을 두 번 재게 된다 |

- 그래서 하방이 막힌 종목은 분모 15%를 받고, 하방이 15%를 넘는 종목은 실측 하방을 그대로 받는다.
  하방이 15~20% 사이면 두 분모가 같은 값이 된다.
- 구현은 `valuation_decision.py`의 `MIN_STOP_LOSS`(0.20)와 `MIN_REWARD_RISK_STOP`(0.15)이고,
  출력의 `risk.effective_stop_loss` · `risk.reward_risk_denominator`가 각각 대응한다.
  **이 표와 두 상수를 같이 고친다** — 테스트가 둘을 비교한다.

**확신도 판정 (§1 「확신도」 칸)**

범위 폭이 1차 축이다. 분산이 곧 불확실성이다.

```
상: 범위 폭 ≤50%   & 5·6단계 모두 수집 & 커버 ≥5사 & 3관점 합치
중: 범위 폭 50~100%, 또는 위 조건 중 1개 결손, 또는 3관점 중 1개 반대
하: 범위 폭 >100%, 또는 컨센·시나리오 한쪽만 존재, 또는 2개 이상 결손, 또는 3관점 갈림
```

**결손 처리 (비블로킹)**

| 상황 | 처리 |
|---|---|
| 컨센 없음 (커버 0사 · 전부 Not Rated · 5·6단계 실패) | `w_c = 0` → 범위 = Bear / 확률가중가 / Bull 그대로 |
| 커버 1사 (최고=최저=평균) | blend 정상. 단 「컨센 산포 1.00배 — 단일 커버」를 명시한다. 폭이 좁은 건 **합의가 아니라 정보 부족**이다 |
| 시나리오 못 세움 (실적 데이터 부족) | 컨센 범위 단독 사용을 §2-D에 명시. 확신도 「하」 상한 |

### 10단계 — 투자 판단 (`advice` 스킬 위임)

단계·단기 바닥 전환(`turn`)·계좌 MDD·이벤트 제한의 결합 게이트는 `scripts/entry_policy.py`에 넘긴다. 알 수 없음은 허가로 승격하지 않으며, 결과의 `action`과 `max_tranche_fraction`을 그대로 기재한다.

방법론은 `../advice/SKILL.md`와 `../advice/references/{value_investing,trend_following,macro,second_level_thinking}.md`.
  `second_level_thinking.md`(막스·클라만)는 별도 섹션을 만들지 말고 **가치 관점의 「이미 가격에 반영됐나」와
  매크로 관점의 사이클 위치 판정에 녹여 쓴다** — §5 섹션 구성은 `template/stock_analysis.md` 고정.

  옮기고(§5 「📋 CAN SLIM 점검」), **판단·확신도·진입 경로·수량에 반영하지 않는다** — 참고 지표다.

  모델이 다시 매기지 않는다. 뒤집으려면 스크립트가 못 본 사실(유증·합병·거래정지 등)을
  근거로 대고 원 판정값도 함께 남긴다.

- **출발점은 9단계 §2-D 판정이다.** 3관점이 이를 뒤집으면 **뒤집는 근거를 명시한다.**
  근거 없이 기대수익 판정과 다른 결론을 내지 않는다.
- 🏛️ 가치 / 📈 추세 / 🌍 매크로 3관점 + **최종 판단(매수 / 관망 / 회피) + 확신도.**
- 세 관점이 충돌하면 충돌을 그대로 드러낸다. 억지로 합의시키지 말 것.
- 승계 작성의 **현재 판단은 처음부터 다시 쓴다.** §5에는 현재 판단만 남기고, 과거 판단과 근거는 §11에 `판단변경` 한 줄로 접는다. 과거 결론에 끌려가지 않되 기록은 없애지 마라.
  - 결론이 달라지면 **무엇이 바뀌어서 달라졌는지** 한 줄로 명시한다 (새 데이터 / 가격 변동 / 과거 오판).
  - 판단이 유지돼도 근거를 다시 쓴다. 「전과 동일」로 끝내지 않는다.
- 룰 환산 **필수** (3단계에서 읽은 원문 기준). 진입가·손절가·익절 라인은 실행 가격이라
  **단일값**으로 낸다. 범위는 목표주가·기대수익에만 쓴다.
  - 진입가 · 「매매규칙 6」 -15% 1차 분할 매도가 · -20% 전량 매도가 원화 환산
  - 「기본 원칙 4. 2%룰」 기준 포지션 상한 — **「매매규칙 9」는 두 축이고 진입 크기를 정하는
    것은 매수원금 축뿐이다.** 둘을 한 min()으로 뭉치지 마라.
    ```
    매수원금 비중 상한 = 2% / 실효 손절폭        ← 진입 크기를 구속하는 값
    평가 비중 상한 = 35%                        ← 진입 후 주가 상승분에 걸리는 별개 상한
    ```
    실효 손절폭은 9단계 값이다. 20%면 매수원금 상한은 10%다. 평가 비중 35%는 **매수로
    넘지 못하는 선이 아니라** 상승으로 넘었을 때 초과분을 줄이라는 선이므로, 진입 수량
    계산에는 들어가지 않는다. 두 값을 각각 적고 어느 것이 지금 걸리는지 명시한다.
  - 「매매규칙 11」 24~30% 익절 라인 (보유량 10~30% 분할)
  - **추세 이탈선(trailing stop) — 단일가.** 매도는 추세추종이다: 추세가 살아 있으면 익절 라인에서
    끊지 말고 이 선까지 끌고 간다. **종가 기준**이다 (`context/my_rules.md` 「적용 방법」
    2026-09-09 확정 — 장중 스파이크로 발동시키지 않는다).
    - 근거는 6단계 `stage_scan` 출력의 **직전 순환적 저점 / 20주선 / 150일선** 또는 경로 B면
      `turn_scan`의 **무효화선(바닥 저점) 중 택 1 + 사유.** 경로 C면 `turn_scan`의 선매집 손절선이다.
      눈대중으로 정하지 마라.
    - 「매매규칙 3(추세 기반 매도)」 — 추세가 꺾이기 전에는 섣불리 팔지 않는다.
    - 24~30% 구간에서 익절 대신 끌고 가려면 「매매규칙 15」 예외 4요건(주도 섹터 1등주 · 20주선
      상승 · 펀더/촉매 유지 · 2%룰 이내)을 항목별로 체크하고 결과를 적는다. 하나라도 미달이면
      「매매규칙 11」대로 10~30% 분할 매도한다.
    - 예외를 적용하든 안 하든 이 선은 **매주 재검토**한다 (「매매규칙 15」 원문).
  - 「기술적 분석 규칙 1」 주봉 20주선 방향 — 하락 중이면 추세 위험이 높다고 보고 **비중과
    진입 시점을 보수적으로** 잡는다. 이 룰은 원문이 "단독으로 매수·매도를 결정하는 절대 조건으로
    삼지 않는다"고 못 박으므로 **그 자체로 진입을 막지 않는다.** 바닥 형성·밸류 매력·펀더 개선·
    촉매를 함께 확인했으면 20주선 아래에서도 분할 진입할 수 있고, 그때는 확인한 4가지를 적는다.
    반대로 20주선 위라는 것만으로 매수 근거를 삼지 않는다.
- **진입 경로 판정 (6단계 `stage_scan` 판정 인용)** — 신규 매수 판정을 낼 때 통과시킨다.
  스테이지는 3관점 중 1표가 아니라 **어느 경로로 들어가느냐를 정하는 게이트**다.
  결합 판정은 `scripts/entry_policy.py`가 낸다 — 모델이 손으로 등급을 매기지 않는다.

  ```
  경로 A (추세 확인 진입) — 판정 `2단계`
    → 매수원금 상한(2% ÷ 실효 손절폭) 전량 배정 가능. 단기 판정은 참고로만 적는다.

  경로 B (가치 우선 진입) — 판정 `1단계` · `3단계` · `4단계`
    → 타이밍 게이트: 6단계 `turn_scan` 판정이 `고개 들기`일 때만.
    → 그리고 아래 밸류 게이트 전 항목 통과 시에만 열린다.
    → 판단 등급은 🟡 관망, 허용 행동은 「매매규칙 4(분할 매수)」 사전 계획의 1차 한정.
       등급과 허용 행동을 따로 적는다.
    → 1차 수량 ≤ 목표 비중 ÷ 3. 나머지 tranche는 증량 트리거 충족 후.
    → 미통과면 신규 진입 수량 0.

  경로 C (고개 들기 전 선매집) — 판정 `1단계` · `3단계` · `4단계`, 단기 판정 `바닥 다지기`
    → `turn_scan` 선매집 가격 조건 충족 + 최근 확정 분기 영업이익 전년 동기 대비 증가(적자 축소 포함)
       + 아래 밸류 게이트 전 항목 통과 시에만 열린다. 「매매규칙 2」 단서 조항이다.
    → 1차 수량 ≤ 경로 B 1차의 절반 (`ACCUMULATION_TRANCHE_RATIO`). 나머지 1차분은 `고개 들기` 뒤에 채운다.
    → 손절은 `turn_scan`의 선매집 손절선(바닥 종가 -3%) 종가 이탈이다. 이것이 이 포지션의 추세 이탈선이다.
    → 영업이익이 감소 중인 턴어라운드는 경로 C 대상이 아니다 — `고개 들기`를 기다려 경로 B로 본다.

  단기 판정 `하락 중` → 🔴. 「매매규칙 2」가 "하락하는 와중에 매수하지 않는다"고 못 박으므로 밸류 예외 없음.
  단기 판정 `바닥 다지기` → 경로 C가 안 열리면 진입 수량 0. `초입 지남` → 진입 수량 0.
             돌파선 / 20일선·앵커드 VWAP 눌림을 감시선으로 적는다.
  `4단계`여도 단기 판정이 `고개 들기`면 경로 B가 열린다 (2026-09-12 사용자 확정). 가치주 바닥은
             150일선상 4단계인 채로 오고, 고개를 든 뒤에는 '하락하는 와중'이 아니다.
  `미수집` (스테이지 또는 단기 판정) → 진입 판단 보류 · 신규 진입 수량 0. 보고서는 계속 쓰고
             재확인할 자료를 남긴다.
  ```

  **밸류 게이트** — 전부 충족해야 경로 B·C가 열린다. 항목마다 근거 1줄.

  1. **하방 막힘 — §2-D 하단목표가 ≥ 현재가.** 무엇이 받치는지 명시한다: 순현금 / 자산가치 /
     Bear 가정의 보수성.
  2. **손익비 ≥ 2.5.** 일반 판정의 2.0보다 높다 — 추세 확인 없이 들어가는 대가다.
     3.0이 아닌 이유: 15% 분모에서 3.0은 중심 기대수익 45%를 요구해 「기본 원칙 2」 본문의
     50%와 겹치고, 20% 분모 시절에는 60%를 요구해 **룰 원문보다 엄격했다**
     (사용자 확정 2026-09-22). 구현은 `entry_policy.py`의 `VALUE_GATE_MIN_REWARD_RISK`.
  3. 「매매규칙 12」 장대 양봉 구간 아님 · 「매매규칙 13」 서프라이즈 원인 규명 완료.
  4. **증량 트리거를 가격 또는 날짜로 명시** — `turn_scan` 감시선의 사다리를 가격으로 옮긴다
     (2026-09-12 사용자 확정, 1/3씩 3단): 2차 = 저점 높임 가격 위 종가 유지 + 60일선 상향 전환,
     3차 = `stage_scan` 2단계 판정 또는 20주선 상승 전환. 촉매 확인일을 더해도 된다.
     무엇이 나머지 tranche를 여는지 안 적었으면 1차도 열지 않는다.

  - ⛔ **기대수익이 크다는 것만으로 경로 B를 열지 않는다.** 하방 막힘이 필수 조건이다.
    같은 이유로 스테이지 판정 자체를 뒤집으려면 `stage_scan`이 볼 수 없는 사실(유증·합병·거래정지·
    상장 초기)을 근거로 대고 **원 판정값을 함께 남긴다. 기대수익이 크다는 것은 뒤집을 근거가 아니다.**
  - 1·3·4단계 매수의 근거는 **밸류이지 추세가 아니다.** 단기 판정은 언제 들어가느냐만 정한다.
    §5 📈 추세 채점이 낮아도 경로 B는 성립한다.
    그 불일치를 §5 「최종」에 한 줄로 드러낸다. 억지로 추세 근거를 지어내지 마라.

- **오버행 참고 (5-1단계 요약 인용)** — §5 「최종」 아래 한 줄로 언급만 한다. 매수 / 관망 / 회피
  판정·확신도·진입 경로·1차 수량은 오버행이 `미해소`·`미수집`이어도 그대로 둔다.
  `entry_policy.py`에도 넘기지 않는다.
- 조건부 룰 — 해당하면 반드시 적용:
  - 6단계에서 **서프라이즈/쇼크 감지** 시 「매매규칙 13」: 진입 조건에
    「서프라이즈 원인 규명 + 장대양봉 소화 후」를 명시한다.
    원인이 일회성(환차익·자산매각·일회성 이익)이면 매수 판정을 🟡로 강등한다.
  - 「매매규칙 12」: 장대 양봉(전일 종가 대비 **+8% 이상**) 구간이면 진입가를 그 위에 잡지 않는다.
    **눈대중하지 말고 6단계 `stage_scan.py` 출력의 「장대 양봉」 줄을 인용한다** — 날짜·등락률·종가가
    같이 나오므로 진입가를 그 종가 아래로 잡는다.
- 판단이 룰과 충돌하면 **룰을 먼저 말한다.**

### 11단계 — 저장

- 경로: `output/reports/종목/<초성>/<종목명>_<yyyy-mm-dd>.md`
  — **2단계 스크립트가 계산해 준 목표 경로를 그대로 쓴다.** 초성 폴더·파일명을 직접 만들지 마라.
- 보고서 종류별 저장 위치:

  | 종류 | 경로 |
  |---|---|
  | 개별 종목 분석 | `output/reports/종목/<초성>/<종목명>_<yyyy-mm-dd>.md` |
  | 섹터·업종·테마 비교 | `output/reports/산업/<yyyy-mm-dd>_<주제>.md` |
  | 전략·스크리닝·순위 등 그 외 | `output/reports/기타/<yyyy-mm-dd>_<주제>.md` |

- 섹션 구성·분량 슬롯의 정본은 `template/stock_analysis.md`다. 이 파일을 읽고 그대로 채운다.

**승계 작성이면 같은 파일을 이름 변경해 이어 쓴다.**

1. 승계본의 전문과 목표 경로를 확인한다.
2. 날짜가 다르면 **승계본 파일명을 목표 경로로 변경한다.** 복사본을 만들지 않는다.
3. 이름을 변경한 같은 파일에서 본문을 현재 상태로 갱신하고, 이번 변경을 §11에 한 줄로 올린다.
4. 11개 섹션이 템플릿 순서대로 현재 상태로 채워졌는지, 이번 변경과 이관한 옛 블록이 §11에 한 줄씩 올라갔는지 확인한다.
5. 과거 작업에서 같은 종목의 날짜별 중복 파일이 남아 있으면, 최신 누적 파일에 고유 내용이 모두 들어갔는지 확인한 뒤 중복 파일을 제거한다.

⚠️ `output/`은 gitignored다. 이름 변경은 정확한 단일 파일에만 수행하고, 기존 목표 파일을 덮어쓰지 않는다.

- **보유 종목의 추가 매수·매도 조건을 정했으면** `output/watchlist/보유_트리거.md`에 그 종목 항목을
  등록·갱신한다 — 매수(증량 tranche·금지 해제 조건)와 매도(추세 이탈선·익절 잔여·실적 훼손) 각각의 조건,
  수량, 폐기 조건, 가격선의 기준일, 보고서 경로. 평단 축 일반선은 스냅샷이 보므로 종목별로 정한 것만 적는다.
  `daily-digest` 1-3-2단계가 이 파일로 매일 충족 여부를 점검한다. 계획이 폐기되면 항목을 지운다.
- 저장 후 사용자에게 **변경된 최종 경로 + 결론 3줄**만 보고한다.
  보고서 전문을 대화에 다시 붙이지 말 것.

## 보조 도구

11단계의 파일 조작과 실행 기록을 손이 아니라 스크립트로 한다. 둘 다 원자적으로 쓰고,
어긋난 상태를 만나면 덮지 않고 멈춘다.

**`scripts/report_update.py`** — 2단계가 정한 승계 규칙의 집행부. 읽은 뒤 원본이 바뀌었으면
(`--expected-sha256` 불일치) `source changed since it was read`로 거절하고, 목표 경로에 다른
파일이 이미 있으면 덮지 않는다. 손으로 `mv` 하다 보면 이 두 가지를 놓친다.
`--update`는 본문 **뒤에 덧붙이는** 도구다. 본문 갱신·옛 블록 이관은 파일을 직접 편집하고,
이 스크립트는 이름 변경 안전장치(스테일·충돌 검사)로 쓴다.

```bash
uv run python .agents/skills/analyze-stock/scripts/report_update.py \
  --source <승계할 보고서> --target <오늘 날짜 경로> --update <추가할 본문.md> \
  [--expected-sha256 <읽은 시점 해시>]
```

**`scripts/run_manifest.py`** — 이번 실행에서 어느 단계가 돌았고 어느 단계가 빠졌는지를
기계가 읽을 수 있게 남긴다. 부분 수집으로 끝난 보고서를 나중에 볼 때 "이 값이 없는 것"과
"이 단계를 안 돌린 것"을 구분하는 근거가 된다.

```bash
uv run python .agents/skills/analyze-stock/scripts/run_manifest.py <매니페스트 경로> \
  --run-id <실행 식별자> --step 6=ok:1200 --step 5=skipped
```

## 출력 품질 기준

보고서 본문은 **caveman full**로 작성한다. 구조는 `template/stock_analysis.md`가, 내용 품질은 아래가 정한다.

- **불릿이 기본 단위.** 문단은 섹션 도입 1~2줄까지만. 3줄 넘는 산문 금지.
- 문장은 짧고 명확하게 쓴다. 조사·군더더기는 줄이되 의미와 조건은 보존한다. 문장 파편 허용.
- 근거·예외·후속 행동이 상위 항목에 종속되면 들여쓴 하위 불릿을 쓴다. 불필요한 계층은 만들지 않는다.
- 나열 3개 이상 + 비교 축이 있으면 **표**로. 리포트별·연도별·보유종목 대비는 전부 표.
- 인과는 짧게 연결한다. 예: `유가 -31%로 스프레드 확대. OPM 10.8%에서 17.8%로 상승.`
- 헤지 표현(「~인 것으로 보인다」, 「~할 수도 있다」) 금지. 불확실하면 **불확실하다고 한 줄로 쓰고**
  무엇을 확인하면 확정되는지 적는다.
- **숫자·단위·기준·출처는 축약하지 않는다.** caveman은 군더더기만 죽인다.
- 완전한 문장 유지: 룰 인용 원문, 공시 원문 인용, 「리스크 · 뒤집는 조건」 절.
- 목표 분량: 섹션당 불릿 3~8개.

## 주의사항

- ⛔ **면책 문구 금지** — 「AI 작성」, 「참고용」, 「최종 판단은 본인」 류를 쓰지 않는다.
- ⛔ **모르면 모른다고 하라.** 리포트가 없거나 MCP가 없으면 그 섹션은 `미수집`으로 남긴다.
  빈칸을 추론으로 채우지 말 것.
- 기준이 다른 숫자를 나란히 놓지 않는다. 연결 vs 별도, TTM vs 분기, 주가 기준일 차이는
  블록쿼트로 경고한다.
- 추정치는 제목이나 표 헤더에 「추정 — DART 데이터 아님」을 붙인다.
- ⛔ **목표주가·기대수익을 단일값으로 쓰지 않는다.** 하단·중심·상단 3점 + 범위 폭 + 산포 비교를
  함께 적는다. 평균 하나는 분산을 숨긴다.
- 아카이브 경로는 환경변수 `INVAGENT_REPORT_ARCHIVE`로 바꿀 수 있다. 절대경로를 문서에 박지 않는다.
