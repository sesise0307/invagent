# Quick Brief — 보유·관심 종목 간이 브리핑

세션 안에서 읽고 끝나는 브리핑이다. **파일을 만들지 않고, StockEasy에 접근하지 않고, 매매 판정을
하지 않는다.** 종가 기준 트리거 판정은 `daily-digest`의 몫이다. 수집 경로의 세부는 `market-data`가
정본이다 — 여기서 다시 적지 않는다.

## 1. 시세·뉴스 수집

```bash
uv run python .agents/skills/quick-brief/scripts/brief_prep.py [--days 2] [--json]
```

- 보유 = 최신 포트폴리오 스냅샷(`output/portfolio/`), 관심 = `context/interested_stocks.md`. 보유가 먼저다.
- 현재가·등락률 = 네이버(장중이면 장중가, 마감 뒤면 그날 가격 — 참고값), 공식 종가 = 금융위 직전 정규장 종가.
- 뉴스 = 네이버 종목 뉴스, `--days` 이내만, 종목당 최대 5건.
- 종료 코드 `0` 정상·부분 수집 · `1` 현재가를 하나도 못 받음. 「미수집」 절의 사유는 그대로 옮긴다 —
  다른 출처 숫자로 메우지 않는다.
- 호스트별 요청 간격 때문에 20여 종목에 2~3분 걸린다. 백그라운드로 돌리고 2단계를 함께 진행한다.

**금지:** `fetch_stock_info.py`·`stage_scan.py`·`turn_scan.py`·`canslim_scan.py`·`fetch_market_signals.py`·
`fetch.py quote`처럼 StockEasy를 타는 스크립트는 부르지 않는다.

## 2. OpenDART 공시

`opendart` 스킬의 MCP 도구로 본다.

1. `risk_events`를 `company` 공백으로 1회 — 시장 전체 최근 30일 횡령·배임·중대재해 중 보유·관심 종목만 남긴다.
2. 종목마다 `company`(query = 종목명, `start_date` = 오늘 - `--days`, `max_recent_filings` 소량)로 최근 공시
   인덱스를 본다. ETF는 건너뛴다. 우선주는 본주로 조회한다. 유의사항의 「최근 공시 인덱스 조회 실패: 013」은
   DART의 「조회된 데이터 없음」 — 기간 내 공시 없음으로 읽는다(2026-10-20 대덕전자 실측).
3. 특이 공시만 추린다: 단일판매·공급계약, 유상증자·CB·BW, 최대주주·5% 변동, 잠정실적, 자사주 취득·처분,
   합병·분할, 거래정지·관리종목. 정기 보고서·임원 소유 소량 변동은 뺀다.

## 3. 뉴스 선별

- 1단계 제목 중 **종목 고유 사건**(수주·실적·소송·규제·신제품·지분)만 남긴다. 시황·지수 기사, 다른 종목이 주인공인
  기사, ETF 출시 기사는 버린다.
- 제목만으로 내용을 알 수 없는 사건만 WebSearch로 1회 보충한다. 시세 숫자는 WebSearch로 바꾸지 않는다.

## 4. 브리핑 (세션 출력만)

최대한 짧게. 표와 불릿을 쓴다. 특이사항 없는 종목은 적지 않는다.

```markdown
**YYYY-MM-DD HH:MM KST · 장중/마감 · 스냅샷 MM-DD**

| 종목 | 현재가 | 등락 | 평단 대비 | 비중 |
|---|---:|---:|---:|---:|
(보유 전부)

| 관심 | 현재가 | 등락 |
|---|---:|---:|
(관심 전부, 한 표)

**특이사항**
- 종목: 한 줄 요약 · 출처(언론사 또는 DART 공시명)

**한 줄:** 오늘 포트 전체 흐름 한 문장 (판정·매매 권고 없이)
```

- 등락 ±5% 이상은 굵게 표시한다.
- 현재가는 네이버 참고값임을 머리줄 「장중/마감」으로 드러낸다. 마감 뒤 가격을 종가 판정 근거로 쓰라고 하지 않는다.
- 미수집 종목은 표에 `미수집`으로 남기고 표 아래 한 줄로 사유를 적는다.
